# Architect proposal F1-F9 (verbatim, sol 01a0e469-af7d, 2026-09-28)

**F1 — Boundary and ownership.** Treat this as a cross-module feature with a public contract change. Today `analyzeAudio` coordinates meters, images, and report generation, while `analyzeFile` owns artifact writes; the CLI consumes its result directly ([src/analyze/analyze.tool.ts:116](../../../../src/analyze/analyze.tool.ts:116), [src/analyze/analyze.tool.ts:210](../../../../src/analyze/analyze.tool.ts:210), [src/cli/commands/analyze.ts:21](../../../../src/cli/commands/analyze.ts:21)). Keep that dependency direction. Put measurement modules under `src/analyze/flow/` and drawing modules under `src/analyze/overview/`; neither writes files or imports the CLI. I reject adding all calculations to `analyze.tool.ts`: it already owns orchestration, and the proposed algorithms need separate tests and performance control.

**F2 — Reuse without changing established measurements.** Extract K-weighting coefficients and the per-sample filtered-power scan from `src/audio-io/loudness.tool.ts` into an audio-io-owned tool. Have the existing meter use the same scan and accumulation order, while flow consumes 100 ms blocks and exact interval power sums; keep gated `integratedLufs` distinct from ungated interval means ([src/audio-io/loudness.tool.ts:12](../../../../src/audio-io/loudness.tool.ts:12), [src/audio-io/loudness.tool.ts:135](../../../../src/audio-io/loudness.tool.ts:135), [002_flow_metrics.md:7](../002_flow_metrics.md:7)). Factor the existing 10 ms flux-envelope calculation so orchestration obtains tempo and onset envelope in one FFT pass; retain `estimateTempo`’s current public return value ([src/analyze/tempo.tool.ts:37](../../../../src/analyze/tempo.tool.ts:37), [src/analyze/tempo.tool.ts:213](../../../../src/analyze/tempo.tool.ts:213)).

**F3 — Flow data contract.** Add a required, additive `flow: FlowAnalysis` near `bands` in `AnalysisJson`, retaining `version: 1` and every existing field’s meaning and relative order ([src/analyze/analysis.schema.ts:45](../../../../src/analyze/analysis.schema.ts:45), [src/analyze/analyze.tool.ts:129](../../../../src/analyze/analyze.tool.ts:129)). Its serializable fields should include `axisKind`, half-open interval times, per-interval ungated LUFS/onset count/onsets per second/centroid, 100 ms momentary and short-term curves, section LU deltas, novelty peaks with declared-boundary hits, repeat ranges and scores, and ordered text annotations. Keep 1,200-column waveform arrays and the full `N×N` similarity matrix in an internal `FlowRenderData`, outside JSON. Add a `## Flow` section to `analysis.md` using those **same annotation strings**; the existing report is derived from `AnalysisJson` ([src/analyze/report.tool.ts:5](../../../../src/analyze/report.tool.ts:5)).

**F4 — Interval and feature computation.** For songs, use `Timeline.secondsPerBar`, `placements.startBar`, and `timeline.durationSeconds` so features exclude render tail ([src/song/timeline.tool.ts:13](../../../../src/song/timeline.tool.ts:13), [src/song/timeline.tool.ts:76](../../../../src/song/timeline.tool.ts:76)). For WAV-only input, use beat intervals only above a documented confidence threshold; otherwise use half-open 0.5 s frames and label the axis accordingly ([src/analyze/beats.tool.ts:28](../../../../src/analyze/beats.tool.ts:28), [002_flow_metrics.md:27](../002_flow_metrics.md:27)). Separate tools should own the three-band waveform; 20-value interval features and SSM; novelty and repeat selection; and onset density plus centroid. Reuse the existing FFT and six band edges, with one explicit spectral pass where feasible ([src/analyze/fft.tool.ts:85](../../../../src/analyze/fft.tool.ts:85), [src/analyze/analysis.schema.ts:8](../../../../src/analyze/analysis.schema.ts:8)). Apply the formulas and thresholds in [002_flow_metrics.md:29](../002_flow_metrics.md:29), [002_flow_metrics.md:39](../002_flow_metrics.md:39), and [002_flow_metrics.md:45](../002_flow_metrics.md:45); its “section K-weighted mean” feature should mean the **current interval’s** mean, or every bar in a section would receive the same value.

**F5 — One-image layout.** Use approximately **1600×1400**: header 0–100, three verdicts 100–170, section band and bar/time ticks 170–310, per-bar LUFS 310–500, arrangement-density lanes 500–620, three-band waveform 620–800, novelty with boundary hits 800–900, and brightness 900–1000. Below that, place global six-band shares and a labeled 256 px SSM inset side by side; reserve the bottom for legends. Align all time panels at `x=136…1168`; keep the section table at `x=1200…1576`. This extends the text-first layout in [003_overview_layout_eval.md:9](../003_overview_layout_eval.md:9) without hiding the measurements required by 002. At a 1024 px long side, 3× glyphs remain about 13 px tall. WAV-only omits declared sections, hook and track-density claims; its table states the axis source, onset summary, peaks and repeats in seconds. Never call inferred intervals “bars.”

**F6 — Text and findings.** Extend the existing 5×7 font with integer scaling, `measureText`, bounded wrapping and required punctuation (`(`, `)`, `|`, `%`, `+`, `=`); unknown characters need a visible fallback because they currently disappear ([src/analyze/font.tool.ts:1](../../../../src/analyze/font.tool.ts:1)). Use three fixed verdict slots: highest-priority existing warning (`CLIPPING`, then `LUFS_OFF_TARGET`, then remaining warning order); largest absolute adjacent section change (`SECTION GAP +6.0 LU INTO HOOK#0 AT B05`); first hook (`FIRST HOOK HOOK#0 AT B05`). Use `NO FLAGS`, `SECTION GAP N/A`, or `NO HOOK DECLARED` when absent. Additional exact annotations include `BOUNDARY B09 MATCHED`, `BOUNDARY B09 MISSED`, and `BARS 5-12 REPEAT 21-28; SIM 0.93`; report and PNG should read from one formatter. Existing warning order is set in [src/analyze/analyze.tool.ts:96](../../../../src/analyze/analyze.tool.ts:96).

**F7 — Artifact and CLI compatibility.** Add `overviewPng: Buffer` to `AnalysisResult` and `overviewPng: string` to `AnalysisArtifacts`, placed after `spectrogramPng`; write `overview.png` through the existing temporary-file/rename path and add it to collision checks ([src/analyze/analysis.schema.ts:58](../../../../src/analyze/analysis.schema.ts:58), [src/analyze/analyze.tool.ts:181](../../../../src/analyze/analyze.tool.ts:181), [src/analyze/analyze.tool.ts:220](../../../../src/analyze/analyze.tool.ts:220)). Insert its path after spectrogram in the CLI artifact array, preserving one-object `--json` output and existing keys ([src/cli/commands/analyze.ts:25](../../../../src/cli/commands/analyze.ts:25), [AGENTS.md:21](../../../../AGENTS.md:21)). Update feature docs and public type exports together ([devlog/str_func/analyze.md:189](../../../str_func/analyze.md:189)).

**F8 — Budget, determinism and proof.** For a 3-minute 48 kHz stereo input, target no more than **15 seconds incremental analysis time and 100 MB incremental peak memory** on the project’s benchmark host; measure against current `analyze` before accepting that target. Keep SSM detection at full interval resolution (`O(N²)`) and downsample only its display; avoid a second full-length K-weighted-power array. Initialize every RGB byte, fix traversal and tie-break order, round JSON only at its current serialization boundary, and compare PNG bytes twice under one Node major and platform ([src/analyze/png.tool.ts:23](../../../../src/analyze/png.tool.ts:23), [AGENTS.md:19](../../../../AGENTS.md:19)). Tests should cover 997 Hz level doubling, three separate band sines, the copied 8-bar stripe, `A×8/B×8/A×8` novelty, boundary clicks, centroid tones and silence from [002_flow_metrics.md:13](../002_flow_metrics.md:13) through [002_flow_metrics.md:57](../002_flow_metrics.md:57). Add artifact and 1024 px readability checks; run the repository gates in [AGENTS.md:9](../../../../AGENTS.md:9) during implementation.

**F9 — Material risks.** A 376 px table rail fits roughly 20 scaled glyphs per line; many section occurrences can exceed the fixed canvas. Define an overflow rule before implementation—prefer growing height while preserving row size, and record when the 1024 px readability target can no longer hold ([003_overview_layout_eval.md:21](../003_overview_layout_eval.md:21)). Crossovers overlap, so three-band RMS must not be presented as an exact decomposition of full-band power ([002_flow_metrics.md:23](../002_flow_metrics.md:23)). WAV beat confidence, dense labels, unsupported Unicode titles and the cost of another FFT pass need focused checks. The image-only VLM comparison in [003_overview_layout_eval.md:29](../003_overview_layout_eval.md:29) is an evaluation gate for readability, not evidence that the design already succeeds.

**Open assumptions:** Set the WAV beat-axis threshold provisionally at confidence ≥0.6 with at least four usable beats, then check it against fixtures. Treat more than about 25 section occurrences as an explicit image-height overflow case. No files were changed and no test or performance claims are made in this read-only proposal.
