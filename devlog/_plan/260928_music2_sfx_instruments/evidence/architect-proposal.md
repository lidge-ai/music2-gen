# Architect proposal: SFX and virtual instruments

Status: proposal, based on the current source on 2026-09-28. No implementation or audio test is claimed here. `F1`–`F9` are recommended dispositions for the parent to accept or revise.

## Current boundary map

Song JSON enters `src/song/song.schema.ts:22-43`, whose `params` are numeric and whose pattern check only checks the **syntax** of drum sample references (`:268-287`). `src/pattern/values.tool.ts:26-31` parses `name:index` but has no instrument-specific name list. The timeline converts drums to sample references and computes event duration from the weighted pattern slot, multiplied by `gate` unless `mono` (`src/song/timeline.tool.ts:55-67`). `@n` is a relative weight in a sequence, 1–64, not n seconds (`src/pattern/parse.tool.ts:62-104`; `src/pattern/query.tool.ts:24-49`). `src/render/render.tool.ts:12-27` rejects unknown **built-in drums** names after timeline construction; `src/render/voices/drums.tool.ts:4-19,77-95` has eight names and four modulo variants. `kit:` bypasses the built-in voice registry and loads a song-relative manifest (`src/render/voices/registry.tool.ts:25-34,43-47`; `src/render/kit.tool.ts:1-49`).

`VoiceEvent` already carries `sample`, `midi`, `velocity`, `startFrame`, `gateFrames`, `stopFrame`, `eventIndex`, and addressed `seed`; `VoiceSpec` returns track-length mono PCM (`src/render/render.schema.ts:7-10`). The mixer selects events, rounds their durations to `gateFrames`, caps mono notes at the next onset, and gives pitched polyphonic voices a release tail (`src/render/mixer.tool.ts:24-62`). The built-in voice registry owns parameter defaults and limits (`src/render/voices/registry.tool.ts:16-71`). The CLI owns command registration, JSON envelopes, output staging, and WAV writing (`src/cli/registry.ts:15-54`; `src/cli/commands/render.ts:53-135`). `src/audio-io/index.ts` exports `writeWav`; FX contracts/processors live in `src/render/fx/`. The intended dependency direction is CLI → SFX public API and render public API; render's SFX adapter → SFX synthesis API; SFX synthesis → shared PRNG/types only. No SFX module should import the CLI or `renderSong`. This is a cross-feature public-contract change; the new `src/sfx/index.ts`, existing `src/render/index.ts`, and command registry are public boundaries to review.

## Dispositions

**F1 — Accept a separate `sfx` built-in voice of `kind:"drums"`; reject a pitched `riser` notes voice for this increment.** SFX atoms are `riser`, `downlifter`, `impact`, `whoosh`, `revcymbal`, `noisebuild`, `subdrop`, `zap`, `crackle`, with optional zero-based `:index` (four documented deterministic variants, modulo four like drums). Example: `{"id":"transitions","kind":"drums","instrument":"sfx","pattern":"riser:1@3 impact@1","gate":1,"params":{"riserSemitones":12,"sweepFromHz":180,"sweepToHz":9000}}`. SFX is sample-name-shaped but synthesized; it has no MIDI or transpose meaning. A pitched rise can later be made by combining a notes voice with FX, without forcing every transition preset to have a note pitch. Rejected alternative: putting these names in `drums` would alter its accepted atom namespace and invite drum parameter coupling. Consequence: Song v1 gains a new instrument ID and accepted atom set, while the wire shape remains unchanged.

**F2 — Accept voice-declared atom names and explicit event-span handling.** Add optional `sampleNames` (or an equivalent readonly atom set) to `VoiceSpec`; declare the existing `DRUM_NAMES` for `drums` and `SFX_NAMES` for `sfx`. Replace the `instrument === "drums"` special check in `render.tool.ts` with a lookup for built-in drum-kind voices. Keep `kit:` manifest validation separate and preserve its arbitrary manifest sample names. Check both `tracks[].pattern` and section overrides during render validation; report the existing `E_SCHEMA` pattern path for unknown names. For `sfx` only, use the full pattern slot as timeline duration independent of the default track `gate:0.9`, then render exactly `min(frames, startFrame + gateFrames)` frames. Do not use `stopFrame === frames` as a license for an unbounded tail. Document `@n` as relative duration, with `riser@3 impact@1` occupying 3/4 and 1/4 of a bar; a one-atom pattern fills its bar. Reject changing every drum/notes gate calculation or parser grammar. Cross-bar sweeps need an explicit supported slow/group pattern example and a checked timeline oracle before being documented as such. This SFX-only duration rule is an intentional behavior choice; no existing instrument changes.

**F3 — Accept a standalone `music2 sfx` command with a dedicated `src/sfx/` feature.** Proposed shape: `music2 sfx --preset riser --seed 1 [--seconds 2] --out effect.wav [--params riserSemitones=12,sweepFromHz=180,sweepToHz=9000] [--json]`. No positional song. `--preset` and `--out` required; `--seconds` defaults per preset, is finite and bounded (propose 0.05–30 seconds), and resolves to an integer frame count at a fixed default 44,100 Hz. `--params` is one comma-separated numeric map initially, parsed once, with unknown/duplicate/nonfinite/out-of-range keys rejected as `E_INPUT`. This avoids ambiguous repeated-flag semantics in `src/cli/args.ts:33-51`. Result: exact-duration 16-bit stereo WAV plus adjacent `<basename>.sfx.json` containing canonical preset, variant, seed, effective seconds, frames, sample rate, resolved parameter values, and generator contract version. JSON CLI mode emits exactly one standard success/failure envelope; `data` reports both paths and resolved parameters, `artifacts` lists both. Sidecar content has stable key order and no timestamp or temporary path. `src/sfx/sfx.schema.ts` owns preset/parameter validation, `presets.tool.ts` definitions, `generate.tool.ts` bounded PCM synthesis, `index.ts` the public API, and colocated `.test.ts` files. `src/cli/commands/sfx.ts` handles arguments and collision-safe staged WAV/sidecar writes, then registers through `src/cli/registry.ts`. A shared SFX synthesis kernel serves both the standalone generator and `render/voices/sfx.tool.ts`; avoid manufacturing a dummy song and calling `renderSong`, which would add arrangement/master/tail semantics to a one-shot export. Reuse `audio-io/writeWav` and its seeded dither. FX processors may be reused through their render/fx boundary for a later explicit chain, but the first standalone contract is dry and needs no new FX type. Reject a second WAV encoder or runtime dependency.

**F4 — Accept new pitched voice IDs without changing `keys` or `bell`.** The existing `keys` is gated FM (`src/render/voices/keys.tool.ts:5-34`), useful but not equivalent to piano or electric piano; `bell` is a decaying FM bell (`src/render/voices/bell.tool.ts`). Add `piano`, `epiano`, `strings`, `brass`, `organ`, `marimba`, `vibraphone`, `glockenspiel`, `kalimba`, `guitar`, `flute`, `choir` as notes-kind voices. Keep each voice's render function and parameter specs in a small `.tool.ts` with colocated tests; extract shared excitation/envelope/filter kernels only for actual reuse. Suggested synthesis targets: piano (multi-partial struck decay and damped release), epiano (tine/bell FM plus key-off), strings (slow attack/bowed harmonic movement), brass (breath and dynamic harmonic brightness), organ (drawbar/additive sustain), marimba/vibraphone/glockenspiel/kalimba (distinct inharmonic partials and decay envelopes), guitar (seeded pluck with nylon/steel brightness/decay), flute (breath plus near-sinusoidal core), choir (formant vowel bank). These are deterministic synthesized approximations, not sampled acoustic instrument claims. Public IDs/parameter bounds require individual voice cards, register tests, and documentation. Keep current voices flat; if the folder becomes hard to scan, group **new** voices under `voices/keys/`, `voices/orchestral/`, `voices/mallets/`, `voices/strings/`, `voices/winds/` with direct registry imports. The structure audit checks top-level `src/<feature>/index.ts`, `devlog/str_func/<feature>.md`, paired `.tool.ts`/`.test.ts`, and a 500-line hard cap (`scripts/structure-audit.mjs:38-57`); repository guidance prefers approximately 400 lines. Do not make an internal convenience barrel solely to hide paths.

**F5 — Accept numeric selector parameters for the first version.** `guitar.type` (or `stringType`) = 0 nylon, 1 steel; `choir.vowel` = 0 a, 1 e, 2 i, 3 o, 4 u; both integer bounded specs. `drums.kit` = 0 classic, 1 909, 2 808, 3 acoustic, 4 lofi. The JSON Song v1 `params` and `VoiceSpec` are numeric (`src/song/song.schema.ts:28,42,88`; `src/render/render.schema.ts:9-10`); extending them with strings for two switches would widen validation, merge, schema, CLI examples, and public types. The FX schema's enum parameters (`src/render/fx/fx.schema.ts:10-18`) are a sound model if named selectors later become important, but do not silently reuse FX `ParamSpec` for voices. Document integer-to-name mapping prominently. `kit` here selects a synthetic drum character, distinct from `instrument:"kit:<path>"` samples. Keep `kit:0` on the current exact drums code path, with the current seed and summation order, so omission and explicit zero produce byte-identical audio. New kit choices may branch into new DSP, not retune the classic preset table.

**F6 — Accept deterministic, bounded DSP and explicit duration/oracles.** Use only the song/CLI seed and `src/shared/prng.tool.ts` with event-addressed hashes; no `Math.random`, `Date`, hidden global phase, or seed affected by the number of unrelated tracks. For SFX, separate deterministic transient and sweep/noise kernels, clamp oscillator/filter frequencies below Nyquist, bound filter state and amplitude, and verify finite PCM before WAV writes. `riserSemitones`, `sweepFromHz`, `sweepToHz` are validated numeric *track-wide* controls; variant changes a stable timbre, not duration. Default per-preset duration and allowed parameter set come from one SFX schema. Test preset-specific envelope direction/energy and spectra: riser/noisebuild increase toward the end; downlifter/revcymbal decay or reverse; impact/subdrop contain an early low-band transient; whoosh/zap/crackle have distinct temporal/spectral fingerprints. Avoid brittle exact spectral snapshots as the sole quality oracle. For the standalone command, exact frame count is `round(seconds * sampleRate)` and JSON reports the realized duration; reject lengths producing unsafe RIFF allocation. Define a provisional performance gate on the actual target Node major/platform: each 10-second stereo preset at 44.1 kHz completes within 2 seconds and stays below 128 MiB additional RSS on the project CI runner; measure before freezing the threshold and profile any failure. One render event is O(its duration in frames); no whole-track per-event buffer allocation.

**F7 — Accept an explicit lint/analyze policy; do not let SFX impersonate drum roles.** `isKick`, `isBackbeat`, and `isHat` currently match `kind:"drums"` plus an atom name (`src/recipes/lint-geometry.tool.ts:57-68`); constrain these rhythm-role predicates and kick/snare track discovery to `instrument:"drums"` or actual `kit:` samples, excluding `sfx`. Check other genre predicates that count active layers or pick the first percussion track (`src/recipes/lint-rules-dance.tool.ts:34-38`) so a transition track does not satisfy a groove requirement. `register_collision` has a hard-coded focal set `lead/bell/pluck/keys` (`src/recipes/lint-layering-harmony.tool.ts:7,51-76`): classify the new lead-like voices (`flute`, `brass`, perhaps `guitar`) deliberately; sustained pad-like `strings/choir/organ` and struck mallets need separate judgment to avoid broad noisy warnings. The generic low MIDI/pan checks already cover new pitched low notes (`src/recipes/lint-layering-low.tool.ts:62-79`); a `subdrop` has no MIDI and needs a dedicated low-band SFX warning only when its actual rendered overlap/level can be assessed, or an advisory note rather than a fake pitch rule. `src/recipes/lint-fx.tool.ts` only tags bass/808 as low instruments; do not classify every SFX event as a low track. WAV-only analyze's spectral balance warnings will see subdrop energy naturally (`src/analyze/balance-warnings.tool.ts`); avoid retroactively changing existing thresholds. Adding an SFX track may intentionally change density/layer warnings; record that as new-song lint behavior, not a legacy-output regression.

**F8 — Require byte identity for legacy songs and deliberate validation behavior changes.** Before implementing, capture raw PCM and 16/24-bit WAV SHA-256 fixtures from representative existing songs for the same Node major, OS, seed and output settings: classic drums with no `kit` parameter, FM keys, supersaw, user `kit:`, FX sends, stems, loop, and partial bars. After implementation compare bytes, frame count, event count, and JSON fields; separately prove new explicit `drums.kit:0` matches the pre-change omitted-kit fixture. The existing seeded WAV dither and current mastering/limiter path must remain untouched for these inputs (`src/cli/commands/render.ts:99-135`; `src/render/mixer.tool.ts:201-240`). Separate negative tests verify `sfx` used as notes, unknown SFX atoms, invalid variants/params, invalid selector integers, and `kit:` coexistence. The new voice ID and atom names are additive. The proposed SFX duration rule, stricter validation of built-in SFX names, command/sidecar output, new lint classification, and optional new `drums.kit` values are behavior changes **only for new inputs**. Do not alter the parser's permissive sample-ref syntax or existing kit manifest behavior to achieve them.

**F9 — Accept docs and delivery in dependency order.** First lock the Song/SFX contracts and legacy fixture hashes; implement SFX kernel/voice/CLI and focused tests; then add voice families and kit variants; finally lint policy and user-facing examples. Update `devlog/str_func/{song,pattern,render,cli}.md`, add `devlog/str_func/sfx.md` and its index entry, update `skills/music2/references/instruments.md` with all voice IDs, numeric selector maps, SFX atom/variant/duration examples, and `kit:` distinction, plus `docs/cli.md` and `docs/song-format.md`. Add one complete example song containing a timed `riser@3 impact@1` SFX track, and one `music2 sfx` standalone example showing the WAV, sidecar, and `--json` envelope. Song recipe cards should change only if a genre genuinely needs these voices; if changed, run `npm run docs:genres:check`. Implementation gates per `AGENTS.md`: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run audit:structure`, plus focused deterministic/performance and CLI tests. This proposal itself changes only this evidence file; no code gates have been run.
