## 1. Types, media view and command contract

[I] The planner takes validated ProjectIR and already prepared media; the CLI alone reads files/renders/writes. `ExportPlan` is the shared F12 shape, while `DawprojectPlan = ExportPlan<DawData>` carries its single ZIP descriptor. Explicit input byte arrays avoid importing filesystem into `src/export/dawproject`:

```ts
export type DawContent = "midi" | "audio" | "both";
export interface DawMedia {
  path: `audio/${string}.wav`; bytes: Uint8Array;
  frames: number; sampleRate: number; channels: 1 | 2;
  owner: { kind: "source"; sampleIndex: number } |
         { kind: "stem"; trackId: string } |
         { kind: "return"; bus: "reverb" | "delay" };
}
export interface DawClipRegion {
  trackId: string; clipIndex: number; startSeconds: number; endSeconds: number;
  // Source interval consumed by wp5 for the original ProjectIR clip.
}
export interface DawData { dawproject: string; entries: string[]; tracks: number;
  content: DawContent; quantization: ProjectIR["quantization"] }
export type DawprojectPlan = ExportPlan<DawData>; // one .dawproject bytes descriptor
export function planDawproject(project: ProjectIR, media: readonly DawMedia[],
  regions: readonly DawClipRegion[],
  options: { content: DawContent; outputName: string }): DawprojectPlan;
export function projectXml(project: ProjectIR, view: DawView): Uint8Array;
export function metadataXml(project: ProjectIR): Uint8Array;
export function writeStoreZip(entries: readonly { path: string; bytes: Uint8Array }[]): Uint8Array;
// XmlNode and serializeXml come only from wp7 src/export/xml.tool.ts.
export function dawNumber(value: number): string; // finite, fixed six decimals, -0 normalized
```

`DawView` is a validated internal projection assigning unique native track, frozen stem and return-track names, media paths and id targets before XML writing. It contains no absolute source/output path; XML and ZIP cannot vary with destination. The CLI may use same-directory temp WAVs and existing path-based `writeWav` to obtain stem bytes (architect F12/E26), with stable wp4 seed identities; it deletes temps before returning. The CLI also supplies one `DawClipRegion` per ProjectIR audio clip from wp5's actual source-region calculation, not an independent guess about stretch ratios; an empty/out-of-file region remains representable in this planner input so it can produce a warning. Require finite `startSeconds>=0`, `endSeconds>=startSeconds`, with `startSeconds` matching resolved `offsetSeconds`; clamp the native view to `source frames/Fs` as specified in §3. For original `ProjectIR.samples` referenced by audio clips, resolve realpaths under the song directory via wp5's `src/shared/paths.tool.ts` `confinedRealpath`, then read the WAV bytes/header. Reject symlink escape, `..`, absolute paths and non-WAV input as `E_ACCESS`/`E_SCHEMA`; never put a source filesystem path in XML. Assign `audio/source-0000.wav`, `source-0001.wav`, ... in sorted `(role,ref)` sample order, `audio/stem-<track-id>.wav` for dry stems and `audio/return-reverb.wav`/`audio/return-delay.wav` for active returns. All entry names are POSIX, unique, relative and NFC-normalized; reject `.`/`..`, empty segments, backslash, NUL and duplicate normalized names. Original WAV bytes are embedded exactly once for repeated clips.

[I] Validate `DawMedia.sampleRate` by owner: original `source` clip media retain the embedded WAV header's integer rate in the decoder's inclusive 8000..192000 Hz range (`src/audio-io/wav.tool.ts:19-30`, V); `stem` and `return` media use exactly `project.sampleRate` (44100 or 48000). For every owner, `frames`, `channels`, `sampleRate` and emitted `Audio@sampleRate` must agree with the embedded WAV header and byte length. No source WAV is resampled merely to satisfy the Song render-rate enum; frozen audio is rendered at that song rate.

`--content` defaults to `both` (F14). `midi` writes editable note/drum tracks and eligible native clip tracks; it has no frozen playback and warns about music2 voice/insert/duck/bus semantics that cannot travel. `audio` writes only active frozen dry-stem tracks plus active return-stem tracks. `both` writes those active frozen tracks, plus **muted** editable note and original-audio tracks to avoid doubled playback; the editable tracks retain channel gain/pan/sends and supported automation for further DAW work. Frozen stems already contain post-fader automation and inserts, so their channel gain is 0 dB, pan centre, sends zero and no copied automation. Return stems are independent audio tracks routed to master; never route them through the effect channels. Effect channels exist as send targets for the editable view, but omit unsupported music2 devices; warn `EFFECT_DEVICE_NOT_PORTABLE`. The receiving DAW still lacks music2's master saturation/limiter, so warn `MASTER_PROCESSING_NOT_PORTABLE`; no claim of sample-identical playback after import (D5, F14/F19/F23).

The CLI requires exactly `dawproject`, one `<song.json>`, `-o`/`--out` ending `.dawproject`; accepted options are `--content midi|audio|both`, `--allow-plugins`, `--plugin-host <JSON-argv>`, `--force`, `--json`. For `audio|both`, a plugin-bearing song requires `--allow-plugins` and the same trusted host resolution as `render`; pass the resulting processor as `RenderOptions.external` to the single stem/return render. Without opt-in, fail `E_CAPABILITY` exit 3 with a hint to use `--allow-plugins` and configure `--plugin-host` or `MUSIC2_PLUGIN_HOST`, before any ZIP staging. `midi` makes no host lookup/spawn and warns that plugin sound is absent; `--plugin-host` without allow is `E_INPUT` (080 §4). F15's shared staging/identity check refuses an existing output (`E_ACCESS`, exit 4), permits replace only with `--force`, and rejects output aliasing the song or an embedded source (`E_INPUT`, exit 2). Success is one standard envelope with `command:"export"`, the `data` above and `artifacts:[absolute-output-path]`; warnings include quantization and every lossy mapping. Errors use the existing one-object JSON failure envelope (`src/cli/output.ts:19-33`). No clock, output path or temp name enters the ZIP bytes.

## 2. XML structure, identifiers and numeric rules

[V] `Project.xsd` has no target namespace; element order is `Application, Transport, Structure, Arrangement, Scenes`. `MetaData.xsd` uses an ordered optional sequence beginning `Title, Artist, Album, ... , Comment` (R3 §2.2–§2.4). [I] Emit UTF-8 without BOM, `<?xml version="1.0" encoding="UTF-8" standalone="yes"?>`, LF and one final LF. The shared wp7 `src/export/xml.tool.ts` serializer, called with `{declaration:"xmlStandalone"}`, accepts only element names/attribute names chosen by code (no arbitrary name interpolation), preserves construction order of children/attributes, escapes text `& < >`, attribute `& < > " '`, rejects invalid XML 1.0 control/surrogate/noncharacter code points, and never serializes `undefined`, `NaN` or infinity. Avoid XML entities other than the five predefined ones. `project-xml.tool.ts` alone formats DAWproject numbers to fixed six decimals before passing attribute strings to `serializeXml`; six decimals provide stable precision for 960-PPQ beat positions (maximum rounding error 0.0000005 beat, below one tick) and are valid XSD `xs:double` lexical values. ALS retains its shortest-round-trip formatter. It may self-close empty allowed elements; no decorative whitespace inside text nodes.

```xml
<Project version="1.0">
  <Application name="music2" version="<package version>"/>
  <Transport><Tempo id="id0" name="Tempo" unit="bpm" value="120.000000" min="20.000000" max="999.000000"/>
    <TimeSignature id="id1" numerator="4" denominator="4"/></Transport>
  <Structure>
    <Track id="..." name="lead" contentType="notes" loaded="true">
      <Channel id="..." role="regular" audioChannels="2" destination="<master Channel id>" solo="false">
        <Mute id="..." value="false"/><Pan id="..." unit="normalized" value="0.500000" min="0.000000" max="1.000000"/>
        <Sends><Send id="..." destination="<effect Channel id>" type="post"><Volume id="..." unit="linear" value="0.250000" min="0.000000" max="1.000000"/></Send></Sends>
        <Volume id="..." unit="linear" value="1.000000" min="0.000000" max="2.000000"/>
      </Channel>
    </Track>
    <Channel id="..." name="Reverb" role="effect" audioChannels="2" destination="<master Channel id>"/>
    <Channel id="..." name="Delay" role="effect" audioChannels="2" destination="<master Channel id>"/>
    <Track id="..." name="Master" contentType="audio notes" loaded="true"><Channel id="..." role="master" audioChannels="2">...</Channel></Track>
  </Structure>
  <Arrangement id="..."><Lanes id="..." timeUnit="beats">
    <Lanes id="..." track="<lead Track id>"><Clips id="..."><Clip time="0.000000" duration="4.000000" playStart="0.000000">
      <Notes id="..."><Note time="1.000000" duration="0.500000" channel="0" key="60" vel="0.787402"/></Notes>
    </Clip></Clips><Points id="..." unit="linear"><Target parameter="<lead Volume id>"/>
      <RealPoint time="0.000000" value="1.000000" interpolation="linear"/></Points></Lanes>
  </Lanes><Markers id="..."><Marker time="0.000000" name="intro"/></Markers></Arrangement>
  <Scenes/>
</Project>
```

The skeleton is structural, not a literal fixed document: omit `<Sends>` if no nonzero send, omit a missing effect Channel, omit `<Markers>` if `project.markers` is empty, and omit `<Points>` if no supported lane. `Channel` child order is always `Devices?, Mute?, Pan?, Sends?, Volume?`; `Arrangement` child order is `Lanes?, Markers?, TempoAutomation?, TimeSignatureAutomation?`; `Points` begins with `Target` then `RealPoint*`. Empty `Markers` is invalid. Each ProjectIR track gets one structural Track in semantic order (`song.tracks` then `audioTracks`, F3/F6), followed by generated frozen/return tracks and master; effect Channels are direct Structure children. Master has no destination; regular/effect channels destination the master Channel. Emit no fake VST, plug-in state, or processor preset (R3 §2.4, §4.2).

[I] Two passes allocate `id0`, `id1`, ... over every referenceable/parameter/timeline element in final XML document order, then fill IDREF attributes from retained node identities. Forward references are allowed; duplicate IDs are not. Check IDREF **target type**, not just existence: `Lanes@track → Track`, `Channel@destination` and `Send@destination → Channel`, `Target@parameter → realParameter`, `Clip@reference → timeline` if alias clips are later added. The current writer emits no alias clip. R3 §2.6 verified `xmllint --schema` can pass a dangling IDREF, so this semantic pass is mandatory.

[I] Beats/velocities/linear controls use finite fixed six-decimal strings, normalized negative zero to `0.000000`; integer keys/channel/meter use base-10 integers. `beat(tick)=(tick/960).toFixed(6)`: 1→`0.001042`, 480→`0.500000`, 960→`1.000000`. A pattern note may carry quantization error from wp2; expose the count/max in data and a warning, never silently retime render. Note `time` within its clip is relative, `duration=max(1,lengthTicks)/960`, `channel="0"`, `key=0..127`, `vel` is ProjectIR 0..1 clamped only by prior validation. For a MIDI-derived velocity 100, `100/127` serializes `0.787402`; drum/SFX/kit keys use wp3 GM/private mapping, with warnings for missing/lossy mappings. Sort notes by `(tick,key,eventIndex)`. One non-looping clip per note track starts at beat 0 and extends to `max(project.lengthTicks, max(note.tick+note.lengthTicks))`; no zero-duration clip. ProjectIR marker `tick` and `name` become ordered `Marker@time/@name`, retaining repeated-section occurrence suffixes.

Static `Tempo` uses `unit="bpm"`, value six decimals, range 20..999; `TimeSignature` uses ProjectIR numerator and denominator 4. Validate exactly one tick-0 tempo/meter point; later maps require a separate design. Track/master Volume maps dB to `min(2,max(0,10^(dB/20)))`, pan maps `(-1..1 + 1)/2`, sends map 0..1 to linear `Send/Volume` with `type="post"`. Clamp a gain above +6.0206 dB to 2 and warn `DAW_VOLUME_CLAMPED` with track id; never hide the difference. `metadata.xml` writes `<MetaData><Title>...</Title><Comment>Exported by music2</Comment></MetaData>` in schema order, omitting absent Artist/other fields. Application version is the deterministic package version, not a wall-clock build label (R3 §2.3–§2.5; F25).

## 3. Clips, native envelopes and semantic validation

[I] A frozen stem/return WAV becomes one `<Clip time="0.000000" duration="<file seconds × bpm/60>" playStart="0.000000">` with one `<Warps timeUnit="beats" contentTimeUnit="seconds">`, a child `<Audio timeUnit="seconds" channels="2" sampleRate="..." duration="<frames/Fs>"><File path="audio/...wav"/></Audio>`, then `Warp(0,0)` and `Warp(file seconds × bpm/60,frames/Fs)`. A loop-folded or non-loop tail is covered by the clip's actual WAV duration, so no samples are truncated. For an editable original ProjectIR clip, first derive `sourceDuration=frames/Fs` and `nativeEnd=min(region.endSeconds,sourceDuration)`. If `region.startSeconds>=sourceDuration` or `nativeEnd<=region.startSeconds`, omit only that native Clip, retain the frozen audio track in `audio|both`, and warn `NATIVE_AUDIO_CLIP_OMITTED` with track ID/clip index. Otherwise emit `Clip@time=clip.tick/960`, `Clip@playStart=0.000000`, and Warps from `(0,region.startSeconds)` to `(nativeDurationBeats,nativeEnd)`. For `stretch.mode="none"`, `nativeDurationBeats=min(clip.lengthTicks/960,(nativeEnd-region.startSeconds)*bpm/60)`; if this is shorter than the requested duration, warn `NATIVE_AUDIO_CLIP_CLAMPED` with track ID/clip index. For other modes, use the positive native source interval and `nativeDurationBeats=clip.lengthTicks/960`, warning `EDITABLE_AUDIO_APPROXIMATION` when stretch/pitch/fade/gain/duck changes the result. `Clip@duration=nativeDurationBeats`; if the source interval was clipped at EOF, also warn `NATIVE_AUDIO_CLIP_CLAMPED`. The child Audio still reports full source file length. In `midi`, omit/clamp the same native clip and warn that no frozen sound is present; in `audio`, no native clip is emitted. The editable track is muted in `both`, while the active frozen track carries wp5's rendered result, including any zero-filled tail. Every File path must identify one ZIP entry, never an external file. `Audio@duration` is full embedded file frames/Fs, even if its Clip selects a smaller region (R3 §2.4/§2.5).

[I] Every emitted `Warps` has at least two `Warp` children in increasing outer `time`; its content times must also increase. Frozen audio starts `(0,0)`; original clips start `(0,offsetSeconds)`. The planner omits unrepresentable native source regions and warns as above; it never emits a zero-duration or out-of-file warp. A negative/nonfinite offset is still an input error. Constant tempo makes two points sufficient. ProjectIR presently has one tempo point; if a later phase adds changes, add a point at each breakpoint and integrate seconds (R3 §4.2). The semantic check compares `Audio@duration` with the actual WAV frame count divided by sample rate within `1e-6` seconds and checks `@channels`/`@sampleRate` against the header. It also checks each `File` path is embedded and every `Note@duration>0`.

Gain/pan lanes come straight from wp6 `ProjectIR.tracks[].automation`, not its 5 ms DSP-smoothed frame curves (`050_automation.md:7,145`). For each editable Track lane, put a sibling `<Points>` under its track `<Lanes>` with `timeUnit="beats"`, `Target@parameter` pointing to that Track's Volume/Pan ID, and one `RealPoint` per source point in original order. Write `interpolation="linear"|"hold"` explicitly; duplicate-time pairs preserve their order and step. Gain points convert dB to linear, Pan points convert `[-1,1]` to normalized `[0,1]`. A linear dB ramp is nonlinear after conversion to linear amplitude, so warn `GAIN_CURVE_LAW_DIFFERENCE` when endpoints differ; do not claim exact DSP equivalence. Unsupported `send.*`, `fx.*` and `param.*` lanes are omitted with target-specific warnings, never silently ignored. No MIDI CC7/CC10 is used to stand in for native mixer automation (V: R1 §3.2, §4.3; D6).

Before ZIP assembly, walk the generated model and assert unique XML IDs, typed IDREF resolution, valid media paths, strictly increasing Warps, finite numbers, nonempty Markers when present, and every Clip's single child timeline. Fail `E_RENDER` exit 5 on an internal model/serialization invariant; malformed user song fields already fail `E_SCHEMA` exit 2 and inaccessible/escaping media fail `E_ACCESS` exit 4 (F16). The XSD tests remain independent: XSD validity alone cannot prove these semantics (R3 §2.8).

## 4. STORE ZIP, deterministic bytes and official-schema gate

[I] `writeStoreZip` accepts ordered entries and never sorts XML before media: `metadata.xml`, `project.xml`, then media sorted by UTF-8 path bytes. Per entry write PKZIP local header signature `0x04034b50`, version-needed 20, general-purpose bit 11 for UTF-8 names, method 0, DOS time `0x0000`, DOS date `0x0021`, CRC-32 of uncompressed bytes, equal compressed/uncompressed uint32 sizes, filename byte length, zero extra length, then filename/data. Central record `0x02014b50` repeats those fields with version-made-by 20, zero comment/extra/external attrs and the recorded local offset. EOCD `0x06054b50` stores entry count, central size/offset and zero comment. All multibyte fields are little-endian; general-purpose bit 3 is clear and there are no data descriptors. CRC-32 uses reflected IEEE polynomial `0xEDB88320`, init/final XOR `0xFFFFFFFF`, with a fixed table built in source. Reject any entry or total archive reaching uint32 overflow, name over 65535 UTF-8 bytes, count over 65535, or a Zip64 requirement with `E_CAPABILITY` exit 3 before allocating the output. No timestamp, mtime, host path, random name, compression heuristic or directory entry enters the archive. This is D13's STORE policy; `.als` uses `node:zlib` gzip in wp7, while this ZIP needs no gzip or runtime package.

[I] Vendor `Project.xsd`, `MetaData.xsd`, `LICENSE` from `https://github.com/bitwig/dawproject` at D16 commit `ee4dcdde75940f30e14e55401a26955a58b8322b` under `tests/fixtures/dawproject/`. Before any XML validation, a test computes SHA-256 of each vendored file and asserts respectively `58e2fd9864772850aac3eab1f3de8693857dc5384df6d29fbc320ae1de2347cc`, `fb3ba378271770dddbcced8990aba537de3d36ff2d58573523460a699221c99f`, and `3aaee5877c9df985f935e40f42f4452182df9e8a8308dcc6cf1a2341458cdfeb`; a mismatch fails even if `xmllint` is unavailable.
