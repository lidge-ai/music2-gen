# 010 — wp2: Logic library tooling and `user:` instruments

## Outcome

An agent on a Mac with Logic or GarageBand runs `music2 library scan`, `music2 library find kick`, `music2 library import <folder> --id dsx-kick-kit --as kit` and `music2 library import <folder> --id lush-pad`, then writes `"instrument": "user:lush-pad"` in any song, without copying files into the song folder or writing scripts. `music2 library verify lush-pad` proves the octave. On machines without the content, `scan` exits 3.

## Diff-level contract

NEW `src/audio-io/aiff.tool.ts` (+ test): `decodeAiff(bytes): { sampleRate, channels: Float32Array[], loop?: {start,end}, baseNote?: number }`. FORM/AIFF and FORM/AIFC with compression `NONE` (big-endian) or `sowt` (little-endian); 8/16/24/32-bit PCM; 80-bit extended sample rate; COMM, SSND (offset/blockSize), INST (baseNote) and MARK/loop when present. Throws `Music2Error("E_INPUT")` on truncation or unsupported compression. Exported through `src/audio-io/index.ts`.

NEW `src/library/`:
- `library.schema.ts` — `LibraryIndex {version:1, roots: string[], scannedAt?: never, instruments: CandidateFolder[], kits: CandidateFolder[], skipped: {caf, exs, other}}` (no timestamps, deterministic order), `CandidateFolder {path, name, category, files, pitched, formats}`, `InstrumentManifest {version:1, id, kind:"sfz"|"kit", entry, role?, source:{folder: string /* basename only */}, zones?: ImportedZone[], warnings: string[]}`, id regex `^[a-z0-9][a-z0-9-]{0,47}$`, validators.
- `roots.tool.ts` — default roots (darwin only): `/Library/Application Support/Logic/{Alchemy Samples,Ultrabeat Samples,Samples}`, `/Library/Application Support/GarageBand/Instrument Library/Sampler/Sampler Files`; `MUSIC2_SAMPLE_ROOTS` (path-delimiter list) and repeated `--root` override; only existing directories are returned.
- `scan.tool.ts` — bounded walk (depth 6, 20k files): a folder is an instrument candidate when ≥3 audio files carry a note suffix (`/([A-G])([#b]?)(-?\d)( M)?\.(wav|aif|aiff)$/i`), a kit candidate when ≥3 one-shots match drum words (kick/bd, snare/sd, clap, hat/hh, open, ride, crash, tom, rim, perc, shaker, conga). Category = path segments under the root. CAF/EXS/AAZ are counted in `skipped`. Index cached at `$MUSIC2_HOME/library/index.json`.
- `catalog.tool.ts` — `findCandidates(index, words, kind?)`: case-insensitive AND match over path segments and file names, ranked by match count then path.
- `pitch.tool.ts` — Hann-windowed Goertzel harmonic product (4 harmonics) scored over candidate MIDI notes; `measureRoot(mono, rate, namedMidi, loop?)` searches octaves of the named pitch class (12..108) inside the `smpl`/AIFF loop or from 250 ms, returns `{midi, offset, confidence}`; `measureAny(mono, rate, start, length)` for verify (quarter-tone grid).
- `import.tool.ts` — `importInstrument(folder, {id, as, filter, octave:"auto"|"none"|number, attack, release, force})`: decode WAV (existing reader) or AIFF, write 24-bit PCM WAVs named `n<midi>[-v<k>].wav` into a temp dir under `$MUSIC2_HOME/instruments/.tmp-<id>`, then rename to `<id>` (transactional; existing id requires `--force`). Instruments: measured keycenter per file (per-file offset when files disagree; `octave:N` forces `named+12N`), zones split at midpoints, rewritten WAVs carry no `smpl` chunk and `tune=0` (see B3), loops kept as SFZ `loop_mode=loop_continuous loop_start/loop_end`; writes `<id>.sfz` and `instrument.json`. Kits: map file names to atoms `bd sd cp hh oh rim perc tom cr rd` (first-match word table; numbered files become indexed variants `bd:0`, `bd:1`, see B6), write `kit.json` v1 plus `instrument.json`. Reports per-file named/measured/offset.
- `verify.tool.ts` — renders C3 E3 G3 C4 (or `--notes`) through `loadSfz`+`renderSfz` at 1 s per note, measures each with `measureAny` 0.4 s into the slot; returns per-note cents error; failing notes > 50 cents.
- `index.ts`.

NEW `src/cli/commands/library.ts` (+ test): `music2 library <scan|find|import|verify|list> ...` dispatching on `args[0]`; options `--root` (multiple), `--kind`, `--id`, `--as`, `--filter`, `--octave`, `--attack`, `--release`, `--notes`, `--force`, `--limit`. Errors: no roots → `E_CAPABILITY` exit 3; bad id/folder → `E_INPUT` exit 2; verify failure → `E_QA` exit 6. Register in `src/cli/registry.ts`.

MOD `src/shared/paths.tool.ts`: storage kinds `library` and `instruments` under `MUSIC2_HOME`.
MOD `src/render/instrument.tool.ts`: `isSampleInstrument` accepts `user:`; `loadSampleInstrument` reads `instrument.json` under the confined user root and dispatches to `loadSfz(..., root)` or `loadKit(..., root)`; kind mismatch → `E_SCHEMA`.
MOD `src/render/kit.tool.ts`: `loadKit` and the kit MIDI metadata loader take an optional confined root.
MOD `src/song/song-daw.schema.ts`, `src/song/song.schema.ts` (conditional call), `src/render/voices/registry.tool.ts`: accept `user:<id>` syntax (id regex), both track kinds; sampled instruments reject params.
MOD `src/project/build.tool.ts`, `src/midi/from-project.tool.ts`, export planners: `user:` is a sampled resource with the same portability warning as `sfz:`.
MOD `src/cli/commands/instruments.ts`: `user` array (id, kind, zones, role) from `$MUSIC2_HOME/instruments/*/instrument.json`.
MOD `src/cli/commands/doctor.ts`: `sampleLibrary: {roots: [...], available: boolean}`.
MOD `docs/cli.md`, `devlog/str_func/{audio-io,library,render,cli,shared}.md` (library.md new).

## Tests (synthetic fixtures only)

AIFF: 16/24-bit big-endian, sowt, truncated SSND, unsupported compression. Pitch: synthetic harmonic tones named an octave wrong are corrected; sine with 1 harmonic; silence → low confidence. Scan: temp tree with note-named and drum-named files, CAF counted as skipped, missing roots → E_CAPABILITY. Import: instrument SFZ zones/keycenters, kit atom map, transactional failure leaves no directory, duplicate id without `--force` fails, id validation. `user:` render: a song under a temp dir referencing `user:<id>` with `MUSIC2_HOME` set renders; escaping symlink → E_ACCESS. Verify passes on a correct import and fails (exit 6) on a deliberately mis-keyed SFZ. CLI JSON single-object checks.

## Risks

Real Apple content is only on the developer's Mac; all automated tests use generated audio. Pitch detection on bass/noisy pads can be wrong: report `confidence` and let `--octave` override. Windows path separators in `MUSIC2_SAMPLE_ROOTS` use `path.delimiter`.


## Audit fold (A round 1)

- **B1 lint roles.** MOD `src/recipes/lint-geometry.tool.ts` (`kitRoleSample` accepts `user:` on drums tracks) and `src/recipes/lint-roles.tool.ts` (`isSampledMelody` accepts `user:`). Test: the same song with a synthetic `kit:` and with the same kit imported as `user:` yields identical lint results.
- **B2 export identity.** NEW `src/sampler/user-instrument.tool.ts`: `userInstrumentRoot()`, `readUserManifest(id)` (confined under `$MUSIC2_HOME/instruments`, id regex, manifest validation), shared by render, export and CLI (sampler sits below render and library, so no cycle). MOD `src/project/project.schema.ts`: `ProjectInstrument` gains `{ kind: "user"; id: string }` (see R2-1); `src/project/build.tool.ts` emits it; `src/cli/commands/export.ts` loads kit MIDI metadata for `user` kits through `loadKitMidiMap(..., root)`; ALS/DAWproject planners and `src/midi/from-project.tool.ts` treat it like `sfz`/`kit` (portability warning, frozen audio keeps sound). Tests: MIDI export of a `user:` kit song uses the kit's note mapping; export warnings name `user:`.
- **B3 WAV metadata.** NEW `src/audio-io/wav-meta.tool.ts`: `readWavSmpl(bytes)` moved out of `sfz-render.tool.ts` (which now imports it; behaviour unchanged). Import measures pitch from audio, rewrites WAVs **without** `smpl`, carries loops as SFZ `loop_mode=loop_continuous loop_start loop_end` (frame-exact, resample-free), and writes `tune=0`; nothing fractional survives, so nothing is cancelled twice. Fixtures: a source WAV with `smpl` pitchFraction and loop → imported instrument renders at the measured pitch (±10 cents) and the SFZ carries the loop.
- **B6 variants.** No round-robin feature. Kit import writes numbered files of one atom as variants of that atom, playable as `bd:0`, `bd:1`…, recorded in `instrument.json.variants` and documented; plain `bd` plays variant 0 as today.
- **B8 provenance gate.** NEW `scripts/asset-audit.mjs` + `scripts/asset-allowlist.json` (path + sha256 of every committed audio file: the bundled `instruments/` libraries and any committed fixture). It fails when `git ls-files` or the `npm pack --dry-run --json` file list contains an audio-like file (`.wav .aif .aiff .aifc .caf .flac .mp3 .ogg .m4a`, or header magic in any file, see R2-2) that is not allow-listed with a matching hash. `package.json` script `audit:assets`; CI `checks` job runs it. Tests generate fixtures at runtime; import artifacts live under `MUSIC2_HOME`, never the checkout.
- **B10 end-to-end.** NEW `tests/e2e/library-flow.test.ts`: synthetic sample root (harmonic tones whose names are an octave wrong, written as AIFF and WAV-with-smpl; drum one-shots named Kick_1/Snare_1/Hi-Hat_Closed), temp `MUSIC2_HOME`; runs the CLI: `library scan --root`, `find`, `import` (instrument + kit), `verify`, a song using `user:` instruments with `layers` (after wp3) → `balance --apply` (after wp4) → `render` → `export midi`. wp2 lands the scan→verify→render part; wp3 and wp4 extend the same test.

## Audit fold (A round 2)

- **R2-1 ProjectIR stays filesystem-free.** `buildProject` emits `{ kind: "user"; id: string }` with no manifest kind. Only async code resolves the kind through `readUserManifest(id)`: render, and the `export` CLI, which resolves every `user:` manifest (and kit MIDI map) up front and passes them as plain metadata into the synchronous `planAls`, `planDawproject` and MIDI projection; their signatures gain an optional `userInstruments` map and keep their return contracts. A `user:` kit may sit on a notes track (pitched kit, as `kit:` allows today); a `user:` SFZ requires a notes track. Tests cover a pitched `user:` kit export.
- **R2-2 push-range asset audit.** `scripts/asset-audit.mjs` has three modes: `--tree` (`git ls-files`), `--pack` (`npm pack --dry-run --json` list) and `--range <base>..<head>` (every commit of the range via `git rev-list`, each compared against every parent with `git diff-tree -r --no-commit-id --diff-filter=AMR <parent> <commit>`, root commits via `git ls-tree -r`; every resulting blob is audited; a synthetic test builds a temp repo where an unapproved WAV appears only in a merge resolution and is deleted afterwards, and the audit fails). Each candidate is flagged by audio extension or by header magic (`RIFF....WAVE`, `FORM....AIF[FC]`, `caff`, `fLaC`, `OggS`, `ID3`) read from the first 12 bytes regardless of size, and must match an allow-listed path + sha256. wp6 runs `--range origin/dev..HEAD` before the push and `--range origin/main..origin/dev` before promotion.
