# Architect proposal: production effects (2026-09-28)

Scope: design evidence only. No source changes or benchmarks were run. Dispositions below are recommendations for the parent to implement or revise. Source anchors: `src/song/song.schema.ts` owns the v1 contract and `SONG_JSON_SCHEMA`; `src/render/mixer.tool.ts` owns mono-to-stereo mixing, two fixed sends, loop folding, and mastering; `src/render/fx.tool.ts` owns the legacy wet algorithms; `src/render/voices/registry.tool.ts` owns voice parameter checks. `src/recipes/lint-layering-low.tool.ts` checks low pan; `src/analyze` measures final WAV. Existing `schema/song.v1.json` is the serialized in-code schema, emitted by `music2 schema --out`.

## F1 — Additive v1 contract and compatibility gate — **accept**

Add optional `track.fx: TrackInsert[]`, `song.fx?: {reverb?: ReverbBus; delay?: DelayBus}`, and `song.master.fx?: MasterInsert[]` to song v1; keep `version: 1`, all existing fields, and existing defaults. An omitted `track.fx` resolves to `[]`, an omitted `master.fx` to `[]`, and an omitted `song.fx` to `null` (presence must remain observable). Permit an empty `song.fx` object; each omitted bus still uses the legacy processor. Existing `sends.reverb`/`sends.delay` keep their meaning as linear levels into wet-only buses. The proposed bus `mix` is a **wet output scalar** [0,1], default 1, never a dry/wet blend that would double-count dry audio. A configured bus replaces only its corresponding legacy processor. Thus `song.fx` absent, even if a track uses inserts, preserves *the legacy send algorithm*; a song with none of the new fields must produce byte-identical PCM/WAV under the same Node major and platform. New fields intentionally change audio; no promise of byte identity applies to those songs.

Keep the existing mono `mixDry` and `applyReverb`/`applyDelay` call path untouched for tracks without inserts and buses without configuration. Avoid moving normalization, float arithmetic, summation order, or old voice branches in that path. Test byte equality against committed legacy PCM/WAV digests for no-FX fixtures, including send, stem, loop, `--bars`, and LUFS cases. A digest is a regression oracle, not a cross-platform guarantee.

## F2 — Track insert topology — **accept; explicit behavior change for `track.fx`**

Signal order: voice or kit renders mono at full allocated length → copy to dual-mono stereo work buffer **only when `track.fx` is nonempty** → apply `track.fx` serially in declared order → track pan → track gain → duck envelope → dry mix, dry stem capture, and pre-send taps → shared wet returns → loop-tail fold → master inserts → existing loudness targeting / gain / soft saturation / peak scaling / limiter / final true-peak correction. Pan, gain, and duck all affect sends and stems exactly as they do now. Stems remain post-insert, post-pan/gain/duck dry tracks, excluding bus returns and master effects. Insert delays process the entire `frames` buffer, so tails are present in stems and can wrap in a loop; tails beyond `tailSeconds` are truncated as with today's send effects. A cropped `--bars` render starts effect state at zero and is not promised sample-equal to a full-song crop for time-dependent effects; event seeds remain addressed to full-timeline indices.

For the stereo path, use balance gains `cos((pan+1)π/4)√2` and `sin((pan+1)π/4)√2` on left and right respectively. At center, intrinsic stereo survives unchanged. At extreme pan, the opposite channel is attenuated rather than folded across; document that stereo tracks should avoid extreme pan if they need both sides. The no-insert mono path retains its exact current arithmetic. Check finite samples after every processor and at the mix boundary; reject NaN/Inf as `E_RENDER` with effect, track, and frame context. Process in-place or with one reused stereo scratch buffer, never retain one full-length buffer per insert.

`width` uses a complementary mid/side split: a matched low-pass at a default 120 Hz defines the mono low band, and `sideHigh = side - lowPass(side)` is the only component multiplied by `width`. Keep the low side at zero, even for width > 1, so sub content is centered before track pan. `width=1` preserves the high stereo side; `width=0` collapses to mono. If `pan≠0`, the subsequent pan can still offset the low band, so lint must continue to warn for low tracks. The same mono-below-cutoff policy applies to master width; its default should use the same 120 Hz and be explicitly parameterized within 80..250 Hz.

## F3 — Insert effects and parameter contract — **accept**

Use a discriminated union with `type` required and effect-specific `additionalProperties:false`. All numbers are finite and inclusive within the ranges below; omitted values receive the shown defaults. `mix` on track inserts is dry/wet [0,1] default 1, except `eq`, `width`, and `compressor`, whose controls describe the entire processed signal and therefore have no `mix` in v1. Effect order is user order and may produce different audio; do not reorder for optimization.

| Type | Parameters (default; allowed) | DSP contract / oracle |
|---|---|---|
| `eq` | `lowGainDb`, `midGainDb`, `highGainDb` (0; -18..18); `lowHz` (120; 40..500), `midHz` (1000; 200..6000), `highHz` (8000; 2000..18000), `midQ` (0.7; 0.2..5) | Cascaded double-precision biquad low shelf, peak, high shelf; 0 dB stages bypass exactly. Check response at each center and finite output at 44.1/48 kHz. |
| `filter` | `mode` (`lowpass`; `lowpass`/`highpass`/`bandpass`), `cutoffHz` (1000; 20..18000), `q` (0.707; 0.2..10), `mix` (1; 0..1) | Stable biquad with coefficient limits below Nyquist. Impulse/FFT cutoff and Q checks. |
| `drive` | `amount` (2; 1..12), `toneHz` (8000; 500..18000), `mix` (1; 0..1) | Gain-compensated tanh shaping, anti-aliasing via bounded 2× oversampling and post low-pass; deterministic no random dither. Sweep/alias and bypass checks. |
| `compressor` | `thresholdDb` (-18; -60..0), `ratio` (4; 1..20), `attackMs` (10; 0.1..100), `releaseMs` (100; 10..2000), `kneeDb` (6; 0..24), `makeupDb` (0; -12..24) | Stereo-linked RMS detector with soft knee and smoothed gain, no lookahead; step response and left/right gain matching. |
| `chorus` | `rateHz` (0.35; 0.05..5), `depthMs` (5; 0..15), `baseMs` (15; 5..35), `feedback` (0; -0.8..0.8), `mix` (0.5; 0..1) | Fractional interpolated modulated taps with fixed L/R phase offset; ring size bounded by max delay. Stereo decorrelation and bounded feedback. |
| `phaser` | `rateHz` (0.3; 0.05..5), `depth` (0.7; 0..1), `stages` (4; 2/4/6 integer), `feedback` (0; -0.8..0.8), `mix` (0.5; 0..1) | Cascaded first-order all-pass stages with bounded feedback, offset stereo LFOs; frequency-notch sweep oracle. |
| `width` | `amount` (1; 0..2), `monoBelowHz` (120; 80..250) | Complementary mid/side high-band scaling above; low-side null and mono-compatibility checks. |
| `crush` | `bits` (8; 4..16 integer), `downsample` (2; 1..32 integer), `mix` (1; 0..1) | Sample-and-hold plus deterministic uniform quantization; no stochastic dithering. Exact level and hold-period vectors. |
| `tremolo` | `rateHz` (4; 0.05..20), `depth` (0.5; 0..1), `phaseDegrees` (0; 0..180), `mix` (1; 0..1) | Sinusoidal nonnegative gain modulation with stable L/R phase offset; frequency/zero-depth oracle. |
| `delay` | `time` (`1/8d`; note-division enum below), `feedback` (0.35; 0..0.95), `pingPong` (false; boolean), `lowCutHz` (20; 20..1000), `highCutHz` (18000; 1000..18000), `mix` (0.35; 0..1) | Tempo-synced delay; filter the feedback path, clamp loop gain, exclude dry in the wet branch. Impulse positions/geometric decay, ping-pong, and cutoff checks. |

Shared note-division enum: `1/16`, `1/16d`, `1/16t`, `1/8`, `1/8d`, `1/8t`, `1/4`, `1/4d`, `1/4t`, `1/2`, `1/2d`, `1/2t`; quarter-note seconds = `60/bpm`, dotted multiplier = 1.5, triplet multiplier = 2/3. Require `lowCutHz < highCutHz` and `lowHz < midHz < highHz` at the source validation boundary. At 44.1 kHz, 18 kHz stays below Nyquist. Limit insert chain to 12 entries per track and reject duplicate or unsupported fields; do not impose an arbitrary order.

## F4 — Configurable shared sends — **accept; explicit behavior change only for configured buses**

`song.fx.reverb`: `{type: "room"|"plate"|"hall", decaySeconds, preDelayMs, damping, lowCutHz, highCutHz, width, mix}`. Recommended defaults: `room`, 1.5 s, 0 ms, 0.5, 80 Hz, 16000 Hz, 1, 1. Inclusive bounds: decay 0.2..8 s, pre-delay 0..250 ms, damping 0..1, low-cut 20..1000 Hz, high-cut 1000..18000 Hz, width 0..2, mix 0..1; require low-cut < high-cut. Use a stable stereo feedback-delay network with preset room/plate/hall diffusion and early-reflection density, decay mapped to RT60 per line, feedback dampers, input/output cuts, predelay, and wet-output width. Keep its output strictly wet, deterministic, and finite at maximum settings. An impulse at frame zero must first emerge no earlier than predelay; measure approximate RT60 by octave bands and verify room < plate < hall under preset defaults.

`song.fx.delay`: `{time, feedback, pingPong, lowCutHz, highCutHz, mix}` with defaults `1/8d`, 0.35, true, 20 Hz, 18000 Hz, 1; same division enum and crossover rule as insert delay, feedback 0..0.95, mix 0..1. A left impulse first appears right for ping-pong and left for ordinary delay. Filter feedback, not merely the input; use bounded ring buffers. If only reverb is configured, delay remains byte-identical to the old delay; vice versa. `song.fx={}` leaves both old buses in place. An explicit `mix:0` silences the configured wet return without changing dry tracks.

Keep a second reverb bus **deferred** for v1 implementation: it would need a new `sends.reverb2` contract, a second potentially large state, lint guidance, and tests. Add it later as another optional v1 field if a concrete use case needs it; do not silently repurpose the existing send.

## F5 — Master inserts — **accept; explicit behavior change for `master.fx`**

Allow only `eq`, `compressor`, `drive`, and `width` in `song.master.fx`, same parameter envelopes as F3, max 4 entries, user order preserved. Recommend `compressor` ratio 1..4 for glue presets in docs, while the schema still allows the general 1..20 range. Process stereo after dry+wet sum and, for loops, after tail folding, then run the existing `masterAudio` loudness measurement and target gain, saturation, peak normalization, lookahead limiting, and true-peak correction. This location means `targetLufs` observes master FX output and the final ceiling remains enforced. No master inserts must take the existing `masterAudio` path without extra float operations.

## F6 — Synth voice expansion — **accept with legacy branches**

Register `supersaw` as a new `notes` voice, polyphonic by default, with `unison` (7; 1..9 integer), `detuneCents` (18; 0..50), `cutoffHz` (3500; 80..12000), `resonance` (0.2; 0..0.9), `filterEnvAmount` (0.5; 0..1), `filterEnvDecayMs` (500; 20..5000), `attackMs` (20; 0..5000), and `releaseMs` (250; 5..5000). Normalize oscillator sum by voice count; fixed phase offsets derived from `song.seed`/event seed via `src/shared/prng.tool.ts`, never `Math.random` or `Date`. PolyBLEP saw and square oscillators use per-sample phase increments, bounded around Nyquist; note-filter state is per event, preserving independent chord voices.

Add optional `unison` (1; 1..9 integer), `detuneCents` (0; 0..50), `filterEnvAmount` (0; 0..1), and `filterEnvDecayMs` (500; 20..5000) to lead/bass. Pad already has `detuneCents` and a three-oscillator legacy sound: retain it; add `unison` with a **legacy sentinel default** (`3`) plus filter-envelope controls, but branch on *presence of any new parameter* rather than merged default value. For lead and bass also branch on explicit new parameter presence so existing `wave` oscillators and state updates are byte-identical; the new branch uses PolyBLEP, unison, and optional envelope modulation. This avoids changing older songs even if they explicitly set original parameters. Preserve bass `mono:true` enforcement and event stop/glide semantics; `supersaw` can be mono only if explicitly requested. Keep first-note pitch and attack/release gates consistent with current `selectEvents` release-tail selection. Verify new PolyBLEP paths against high-note alias-energy and deterministic chord/seed oracles; do not claim the old saws are band-limited.

## F7 — Validation, errors, schema, and module ownership — **accept**

Define effect unions and parameter specs in `src/render/fx/fx.schema.ts` or a shared song-facing schema module without importing render runtime into `src/song`; one declarative rule source should build the in-code JSON Schema and validate/normalize runtime objects. The current homegrown JSON Schema checker supports `oneOf`, `enum`, numeric bounds, array bounds, and `additionalProperties:false`, but not `$ref`, `allOf`, `if/then`, or `multipleOf`; extend it deliberately or emit explicit discriminated `oneOf` branches. Set `required:["type"]` for each branch and `additionalProperties:false` to reject unknown effect types and misspelled parameters. Validate both raw input and direct `ResolvedSong` calls; throw `Music2Error("E_SCHEMA")` with `details.issues` paths such as `$.tracks[2].fx[1].feedback`, `$.fx.reverb.decaySeconds`, and `$.master.fx[0].type`. Do not defer bad configurations to `E_RENDER`; reserve that for nonfinite DSP output or allocation failures. Preserve existing voice-param path format until a separate migration, but align new effect paths with song's `$` convention.

Split processors by responsibility under `src/render/fx/`: `index.ts` chain/bus dispatch, `fx.schema.ts` types/ranges, `biquad.tool.ts`, `dynamics.tool.ts`, `modulation.tool.ts`, `delay.tool.ts`, `reverb.tool.ts`, `width.tool.ts`, with adjacent focused tests. Keep `src/render/fx.tool.ts` as the unchanged legacy reverb/delay/duck owner initially; migrate only when byte-equivalence is proved. Extract mixer planning and mastering helpers if `mixer.tool.ts` would exceed its current 290 lines by much; keep files near 400 lines. Update `src/render/render.schema.ts` only for types needed at the render boundary, `src/render/voices/registry.tool.ts` and `index.ts` for the new voice, and `src/song/song.schema.ts` for public song types/normalization. Regenerate `schema/song.v1.json` with `music2 schema --out schema/song.v1.json` and assert exact file equality to the in-code value. No runtime package dependencies.

## F8 — Determinism, time, and memory — **accept as a measurable budget**

At 48 kHz, 180 s has 8.64 million frames. Ten tracks × 3–4 inserts is roughly 259–346 million stereo-frame stage visits (518–691 million channel-sample operations) before voices, sends, and mastering; this is an operation estimate, **not a measured runtime**. Target <=60 s on the project's reference machine for a 180 s, 10-track, 35-insert render without stems, and <=3× the same song without inserts; record machine, Node major, wall time, and peak RSS. Revisit the target after the first measured baseline. At that length one full stereo Float32 buffer is ~69 MB; reuse a single track scratch stereo pair, small delay rings, and existing shared sends, rather than allocating 35 full-song outputs. Existing master + two sends alone are ~207 MB; optional ten stems add ~691 MB, so benchmark stems separately and state memory cost. No per-frame object creation or trigonometric/coefficient recomputation in a hot loop; calculate LFO phase increments and static biquad coefficients once, and use bounded ring storage for delays/reverb. Preserve deterministic track iteration and summation order. Check on the same Node major/platform; float output across platforms is not guaranteed byte-identical.

## F9 — Tests, CLI, docs, lint, and analysis — **accept**

Test schema bounds, unknown types/keys, cross-field ordering, indexed `E_SCHEMA` paths, and direct `ResolvedSong` validation. Test impulse/step/frequency oracles from F3–F4 at 44.1/48 kHz, max feedback stability, no denormals/nonfinite values, hard-pan/center stereo, pre/post-send ordering, duck taps, dry stem meaning, tail truncation, loop fold, `--bars` effect reset, ceiling after master FX, and same-seed PCM equality. Keep old fixtures/digests byte-identical. Run affected source gates required by `AGENTS.md` when implementation lands: typecheck, lint, test, build, audit:structure; benchmark is separate from the normal suite. No full suite was run for this document.

The existing render CLI can accept new song JSON without new flags. Update `music2 render` help/examples, `skills/music2/references/instruments.md` and `mixing.md`, schema and feature docs (`devlog/str_func/song.md`, `render.md`, `cli.md` if output semantics change), plus the end-user skill entry and relevant genre cards only where examples change. Explain `tailSeconds`, wet-only sends, `master.targetLufs` order, dry stems, and mono-below width. Keep `--json` one object and current exit mappings (schema invalid = exit 2). In `src/recipes` lint, add advisory rules for nonzero reverb on `808`/bass, delay feedback >0.9, and width on low tracks (including master width only if low side is not protected); retain `generic/low_pan` because track pan follows width and can move the low band. Do not reject musically intentional settings. Existing WAV `analyze` and layering checks need no schema change: they see post-FX PCM, so spectral/loudness warnings can shift; document that `generic/clipping_risk` is static and ignores compression/limiting, and compare before/after analysis at the same song/genre. Add a focused stereo low-band correlation/side-energy check only if an analyzer feature is separately scoped; do not infer mono compatibility from pan alone.
