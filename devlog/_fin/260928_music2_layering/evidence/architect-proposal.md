# Instrument layering checks — architect proposal

## Recommendation and boundary

Add high-confidence, deterministic *song-source* checks to recipe lint, and keep measured spectral balance in analyze. Ship F1, the dance half of F2, F5, and a calibrated F6 first. Pilot F3/F4 against fixtures before enabling their warnings. Defer trap/drill onset-only F2 and F7 until they can avoid the existing arrangements' deliberate layering. This is a C3 design proposal; no source or contract was edited here.

Current direction: `song` validates and builds `TimedEvent[]` → `recipes` owns static heuristics; `render` turns voices into PCM with gain/pan/duck → `analyze` owns measured bands and warnings. `lintSong` already builds a timeline and geometry before generic/genre checks (`src/recipes/lint.tool.ts:101-109`). Keep new helpers internal to `recipes`; no new public export or `song`/`render` dependency is needed. `analyzeAudio` already accepts `opts.song` and routes song warnings (`src/analyze/analyze.tool.ts:150-171`). Rejected alternative: putting all checks in `analyze`; WAV-only input cannot identify note/track ownership, and static checks would then require rendering and duplicate the lint contract. Blast radius is two features and the existing CLI JSON/QA behavior, not the song schema.

### Evidence and measurement rules shared by F1–F7

`TimedEvent` supplies track/index, MIDI, onset seconds, nominal duration, velocity, bar, and order (`src/song/timeline.tool.ts:8-14,64-77`). `ResolvedTrack` supplies instrument, kind, gain dB, pan, mono, params, and `duck` (`src/song/song.schema.ts:31-45`). `LintGeometry.events` groups events by bar and has placements/roles; `isKick` recognizes drum atom `bd`, not merely a track named kick (`src/recipes/lint-geometry.tool.ts:5-35,107-122`). Use absolute `time`, half-open intervals, and sorted sweep endpoints for simultaneous notes; bar co-occurrence is insufficient. Clamp mono notes at the next same-track onset as the mixer does (`src/render/mixer.tool.ts:23-55`), and consider release tails as an uncertainty, not an exact overlap fact. Skip silent velocity and very low effective level; gain is `10^(gain/20)`, while voice envelopes/spectra are instrument-specific (`src/render/mixer.tool.ts:250-263`). Report bounded evidence (track IDs, section occurrence/first bar, observed fraction), sort deterministically, and emit one finding per cause/section rather than every note pair. No random sampling, clock, floating FFT, or external dependency belongs in static lint.

`LintResult.severity` is currently only `error | warning`; `--strict` fails on **any** warning with `E_QA`/exit 6 (`src/recipes/lint.tool.ts:11-12`; `src/cli/commands/lint.ts:19-35`). Therefore every *emitted* new lint check below is `warning` and becomes a strict failure. “Info” below means a proposed advisory **not emitted** in the first release; adding `info` would require changing `LintResult`, report counts/sort/text/JSON and defining strict semantics, which is not minimal. Analysis warnings have codes but no severity and are unaffected by lint `--strict` (`src/analyze/analysis.schema.ts:42-62`).

MIDI 46 is B♭2, about 116.5 Hz; C3 is MIDI 48, E3 is 52. MIDI 55–71 spans about 196–494 Hz but is **fundamental pitch**, while the measured `lowMid` band is 250–500 Hz and includes harmonics of much lower notes (`src/analyze/analysis.schema.ts:8`; `src/render/voices/eight-o-eight.tool.ts:32-40`). The 808 is a driven sine with `tanh`, bass is a filtered saw/square (default 600 Hz cutoff), and pad is a detuned filtered saw (default 1800 Hz cutoff): equal MIDI does not mean equal spectral masking (`src/render/voices/eight-o-eight.tool.ts:48-60`; `src/render/voices/bass.tool.ts:20-53`; `src/render/voices/pad.tool.ts:6-28`). A kit/unknown instrument cannot be assigned a reliable spectrum from its label. Avoid treating MIDI as an audio band measurement.

## Numbered proposals

### F1 — Low-end ownership: recommend ship after fixture calibration

**Home:** new `src/recipes/lint-layering-low.tool.ts` plus colocated test, invoked from `lint.tool.ts` with `LintGeometry`; keep `lint-geometry.tool.ts` as timing/role primitives and `lint-generic.tool.ts` as the small existing generic catalogue. Emit `generic/low_end_overlap` warning when **two distinct audible note tracks** carry MIDI ≤46 for a material fraction of the same placement or for repeated ≥~100 ms overlaps. Use duration-weighted overlap, velocity and track gain to exclude quiet pads; identify owners as 808/bass or a genuinely low note voice, not ID text. No song schema change. `--strict` fails on the warning. False positives: `examples/drill-140.song.json:43-69` has 808 plus low `g2/bb2/d3` pad in its hook, but its pad is −16 dB and slow-attack; a simple pitch test would fire on intentional texture. The other inspected examples have one low owner, including `trap-150` (pad starts A3) and `house-124` (pad starts A3). Calibrate using dry stems/ear, then fix either arrangement or detection threshold. Same seed/Node major produces the same timeline and result.

### F2 — Kick/bass onset management: ship dance rule; defer trap/drill rule

**Home:** new `src/recipes/lint-layering-rhythm.tool.ts`, called through `lint-rules-dance.tool.ts` for house/techno; if later enabled for trap/drill, dispatch from `lint-rules.tool.ts`. Use `isKick`, actual seconds with a small tolerance, the kick source track ID, bass/808 note onsets, and `duck.by/amount`. In house/techno, emit `house/kick_bass_unmanaged` or `techno/kick_bass_unmanaged` warning only if repeated kick/bass attacks coincide or bass sustains through kick transients, **and** that bass track lacks meaningful duck by the kick source or demonstrated temporal separation. A `duck` by an all-drums track also ducks on hats/snares (`src/render/mixer.tool.ts:257-260`); inspect source events before treating it as clean kick duck. `--strict` fails. `examples/house-124.song.json:56-67` already ducks bass by kick and should pass; `examples/game-loop-16bar.song.json:83-92` has repeated kick/bass coincidence without duck and likely warns. The house/techno card starter basses also omit duck despite their text calling for duck or separation (`src/recipes/cards/house.ts:47,126-129,222-240`; `src/recipes/cards/techno.ts:46,128-131,222-239`), so fixture expectations or starters need explicit review before enabling strict QA.

For trap/drill, kick and 808 attacks coinciding is often deliberate: `examples/drill-140.song.json:43-49`, `examples/drill-uk-moving-snare-144.song.json:75-91`, `examples/short-30-bed.song.json:75-91`, `examples/trap-150.song.json:45-52`, `examples/trap-hook-first-142.song.json:75-91`, and `examples/type-beat-trap-140.song.json:75-91` all do so. The card text asks for kick/808 separation or preserved transient but offers no machine-readable “separation rule” (`src/recipes/cards/trap.ts:45,103-106`; `src/recipes/cards/drill_uk.ts:46,104-107`). Do not warn on coincidence or absence of duck alone. A later warning needs evidence of sustained low-band collision or an explicit, reviewed rule (for example onset staggering or shortened 808 at kicks). Until then this is info-only design guidance, not emitted and not strict-failing.

### F3 — Low-mid mud and low chord spacing: pilot, then selective warning

**Home:** new `src/recipes/lint-layering-harmony.tool.ts`, invoked by `lint.tool.ts`; use the same overlap sweep as F1. Candidate `generic/low_chord_spacing` warning: repeated simultaneous intervals ≤4 semitones with the lower pitch below C3/E3 (use a named, voice-aware threshold, not a universal hard musical law). Candidate `generic/low_mid_density` warning: several *audible, independently sustained* note voices whose fundamentals land near MIDI 55–71 during a material slice, weighted by gain; do not count a single chord's three or four keys as three competing tracks. `--strict` fails only if calibrated warnings are enabled. `examples/drill-140.song.json:62-69` has low close-voiced pad chords and would likely fire a naive low-spacing rule, although the pad is quiet. `examples/boom-bap-90.song.json:61-70` and `examples/lofi-75.song.json:72-80` have intentional dense keys voicings; raw simultaneous-note count would falsely flag them (the read-only timeline scan found up to 9 and 10 MIDI-55–71 notes respectively). `house-124` pad chords are in a higher register. Prefer F6's measured `LOW_MID_BUILDUP` for actual mix judgment, and reserve static F3 for clear arrangement-level risk. No schema change; deterministic event and level calculations.

### F4 — Register collision: pilot, then warning

**Home:** `src/recipes/lint-layering-harmony.tool.ts`. Candidate `generic/register_collision` warning requires two *distinct melodic* tracks, substantial same-placement temporal overlap, and repeated pitch-span overlap in the same octave (for example a large intersection/union ratio), excluding bass/808, inaudible layers, and isolated unisons or call-and-response. `--strict` fails only when enabled. `examples/boom-bap-90.song.json:61-80` has keys plus hook stab and is the most likely naive false positive; the stab is sparse and a separate higher voice. `house-124` has pad and lead concurrently, but their ranges are mostly separate; `trap-150` pad and pluck likewise. The other examples mostly have one melodic track. Do not infer masking from range intersection alone: FM keys, bright lead, bell, and filtered pad have different spectra. No contract change; same event list yields deterministic evidence.

### F5 — Center low tracks: recommend ship

**Home:** `src/recipes/lint-layering-low.tool.ts` as `generic/low_pan`; check resolved `pan` of each *audible* `808`/`bass` track (warn beyond a small center tolerance such as |pan| >0.05), plus non-bass tracks only if they carry material MIDI ≤46 content. `--strict` fails. All inspected examples and seven recipe starters have centered low tracks; no expected existing-example warning. `src/render/mixer.tool.ts:63-76` pans the entire mono track with equal-power gains, so a low note on a mixed-register track cannot be centered independently by lint; warn on the track control and suggest splitting the low voice. Stereo wet sends can still spread low energy; this static finding is not proof that rendered low band is centered. No schema change and deterministic.

### F6 — Genre-aware measured balance: recommend ship with measured calibration

**Home:** new `src/analyze/balance-warnings.tool.ts`; `analyze.tool.ts` passes the existing `opts.song?.genre` into it. Keep whole-file `measureBands` and its six shares in `bands.tool.ts` unchanged (`src/analyze/bands.tool.ts:8-69`). Preserve the `LOW_END_DOMINANCE` code and numeric `observed`/`threshold` shape, but select a **genre-specific upper guard** for `sub + low` (20–250 Hz). Add `LOW_MID_BUILDUP` for `lowMid` (250–500 Hz), guarding silence and unusual narrow-band test signals. Suggested starting *review bands*, not validated production thresholds: trap/drill low share 0.25–0.70, lowMid 0.05–0.35; house/techno 0.15–0.60, 0.08–0.38; boom bap/lofi 0.12–0.62, 0.10–0.42. Lower edges are descriptive only: intros, breakdowns, and bass-free beds should not warn for being low-light. A warning fires only above the calibrated upper edge, with fixture render measurements and listening receipts required before freezing each constant. Unknown song genre and WAV-only input retain conservative generic `LOW_END_DOMINANCE >0.55`; propose generic `LOW_MID_BUILDUP >0.45` only after validating its false-positive rate. `opts.song` is present for JSON input and WAV `--song`, and absent for WAV-only (`src/analyze/analyze.tool.ts:228-260`); no new CLI option or song field. `--strict` does not govern analyze warnings. The whole-file warning can be dominated by a long sparse section or master processing; instrument gain, kick energy, 808 drive, bass cutoff, and pad filter all affect the actual shares. Likely candidates for a blanket 0.55 false positive are bass-forward `minimal.song.json`, `drill-140.song.json`, `trap-150.song.json`, and low-heavy boom-bap; these are **hypotheses**, since this review did not render their PCM. Adding the code to `AnalysisWarning.code` is an additive TypeScript/JSON warning-contract change. Changing when `LOW_END_DOMINANCE` appears and its threshold/message is a behavioral change to `analysis.json`, `analysis.md`, summary warnings, and flow annotations (`src/analyze/analyze.tool.ts:167-173`); preserve the code name for consumers and document the altered firing policy. No version bump is necessary for an additive warning code if consumers already tolerate unknown codes, but verify downstream consumers first.

### F7 — Too many simultaneous melodic layers: defer

**Home if calibrated:** `src/recipes/lint-layering-harmony.tool.ts` as `generic/melodic_layer_crowding`; count unique audible, non-bass pitched tracks that overlap at an instant inside each section occurrence, not event count, total tracks, or a static section layer count. Consider a warning only for a sustained high count plus register collision; otherwise keep as non-emitted info. `--strict` would fail only on an enabled warning. Existing `active()` and `no_density_contrast` concern onsets/tracks by bar or whole-placement track presence, not peak simultaneous melodic layers (`src/recipes/lint-geometry.tool.ts:56`; `src/recipes/lint-generic.tool.ts:78-90`). The inspected examples reached at most two simultaneous non-bass melodic tracks in a read-only timeline scan; no likely baseline finding. A fixed count punishes intentional unison doubling, quiet textures, and hooks; no schema change, deterministic if enabled.

### F8 — Per-section band balance: optional follow-up, not free from flow

`flow.sectionMeans` contains loudness, not band shares (`src/analyze/flow/flow.schema.ts:19-24`). `flow` has exact song bar intervals (`src/analyze/flow/intervals.tool.ts:5-13`) and internal six-band FFT powers while computing features, but converts them to log-scaled, normalized similarity vectors and discards raw power (`src/analyze/flow/features.tool.ts:41-46,68-81,92-114`); RGB three-band waveform uses 200/2000 Hz crossovers, unlike the six analysis bands (`src/analyze/flow/bands3.tool.ts:31-68`). Thus neither `flow.analysis` nor RGB columns can cheaply yield accurate section `sub+low`/`lowMid` shares. If section-specific balance is required, accumulate raw six-band power by placement in the existing FFT pass and expose only an internal result to F6, or call `measureBands` on PCM section slices at extra FFT cost. Prefer an internal accumulator after profiling; do not reinterpret the normalized vector, add a public `FlowAnalysis` field, or emit WAV-only section verdicts without trustworthy section boundaries. No initial contract change. Any later public per-section metric needs explicit schema/version review.

## Implementation and acceptance boundary for the parent

Split static work into `lint-layering-low.tool.ts` (F1/F5), `lint-layering-rhythm.tool.ts` (F2), and `lint-layering-harmony.tool.ts` (F3/F4/F7); add colocated focused tests. `lint-geometry.tool.ts` is 122 lines, `lint-generic.tool.ts` 100, `lint.tool.ts` 113, `analyze.tool.ts` 287, and `mixer.tool.ts` 290: separate the new balance policy to keep each near the repository's 400-line guide, without changing render DSP. Update `devlog/str_func/recipes.md` and `analyze.md` when implementation changes responsibilities or warning contracts. Add a focused fixture matrix for intentional/accidental overlaps, simultaneous attacks with/without real kick duck, low chords at different gain, center tolerance, and genre/WAV-only spectral thresholds; assert deterministic IDs, ordering, observed values, strict exit 6, and analysis warning JSON/report/annotations. Use the repository's required source gates for the later implementation, including `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run audit:structure`; `npm run docs:genres:check` applies if recipe cards change. This delegated architecture review ran no full suite and changed no source.

Example evidence was obtained by reading all top-level `examples/*.song.json` and running a read-only `validateSong`/`buildTimeline` scan on them; it is **not** a listening test or a rendered-spectrum measurement. The candidate thresholds must be calibrated against rendered baseline fixtures before marking F1/F2/F3/F4/F6 production-ready.
