# Main binding decisions (wp1)

These decisions bind every decade doc in this unit. Where they differ from the architect proposal, this file wins.

D1 Accept architect findings F1–F29 in evidence/architect-proposal.md as the design baseline, including: tick math in src/shared/ticks.tool.ts (PPQ 960); render keeps float-second pattern events and does not consume ProjectIR (F2); ProjectIR built purely from ResolvedSong + Timeline in src/project (F3/F4); Song v1 stays version 1 with optional, absent-in/absent-out fields track.notes, top-level audioTracks, automation lanes and instrument "sfz:<path>" (F5–F9), defined in src/song/song-daw.schema.ts; list notes enter the Timeline through src/song/timeline-notes.tool.ts only when present (F10); render integration is gated per F11 so legacy songs execute the same float operations.
D2 Feature folders: src/project, src/midi, src/sampler, src/automation, src/export, src/plugin-host, each with index.ts public boundary, colocated tests, one devlog/str_func/<feature>.md each, acyclic imports per F13 (render never imports project/export/midi/cli/plugin-host; sampler never imports analyze).
D3 CLI per F14/F15/F16: `music2 export <midi|stems|als|dawproject|ir> <song.json> -o <path>`, `music2 import midi <file.mid> -o <song.json>`, `music2 slice <file.wav> -o <dir>`; existing outputs refused with E_ACCESS exit 4 unless --force; --json prints one object; only existing error codes.
D4 MIDI per F17/F18 and evidence/aside-notes/R1: SMF type 1, PPQ 960, track 0 = tempo (FF 51), time signature (FF 58), key signature (FF 59 when key declared), section markers (FF 06); one MTrk per music2 track with FF 03 name and a FF 01 text event "music2:<instrument>"; notes on channels 1–9/11–16 in track order, drum-kind tracks (drums, kit:, sfx) on channel 10 using a GM drum map, sfx atoms in a documented private note range; running status allowed on write only when proven by fixtures; reader accepts format 0 and 1, running status, velocity-0 note-off, and ignores SysEx safely.
D5 Stems per F19 and R1: stems are post-insert, post-fader, pre-bus per track plus separate reverb and delay return stems and an optional master; a manifest JSON records bpm, meter, key, sample rate, bit depth, length in samples, section markers in bars/seconds, and per-stem file names; the sum of all track stems plus return stems equals the pre-master mix within the documented tolerance (master processing, limiter and loudness are applied only to the master file).
D6 Automation per F7/F21 and R1: portable curve model = points {at beats, value, curve linear|hold}; MIDI export maps gain→CC7 (dB to 0..127 via documented law), pan→CC10, other targets to documented CCs or omitted with a warning; DAW exports (als, dawproject) write native envelopes where possible.
D7 Sampler per F20, R2 and R4 (when available): SFZ subset from R2 §3.2/§6 (regions, key/velocity ranges, pitch_keycenter/keytrack, tune/transpose, volume/amplitude/pan, offset/end, loop modes, trigger attack/release, ampeg DAHDSR, group/off_by, seq_length/seq_position, lorand/hirand with seeded draws, #define/#include/default_path); unsupported opcodes warn, never silently change output. Resampling kernel, time-stretch method and slicer defaults come from R4.
D8 Ableton .als (wp7) and DAWproject (wp8) follow F22/F23 and R3. DAWproject is validated with xmllint against the official MIT-licensed Project.xsd and MetaData.xsd (vendored with license under a test fixture path) and packaged as a zip written by a zero-dependency STORE zip writer with fixed timestamps. .als uses node:zlib gzip with a forced OS header byte and fixed mtime; the element skeleton comes only from documented or permissively licensed sources; the Live-open status is recorded as unverified unless a human confirms.
D9 Plugin bridge (wp9) per F24 and R4: subprocess JSON+WAV contract; the host command comes only from user config or an explicit CLI flag, never from song files; doctor reports availability; missing host is E_CAPABILITY exit 3; stub-host contract tests; plugin-rendered tracks are excluded from byte-determinism claims.
D10 Legacy proof per F27: existing digest tests stay green; before wp2 lands, record baseline digests for every example's render, stems, validate, events and lint output and keep a test that compares them; the regenerated schema/song.v1.json only adds optional properties.
D11 Research hygiene: no GPL/AGPL/LGPL source is read or copied; aside notes are evidence, cited by section; the agent cannot hear, so every audio claim rests on numeric oracles.
D12 .als template provenance (amends D8): do not vendor Ableton's bundled DefaultLiveSet (even via an MIT-labelled copy) because Ableton's rights over that content are unclear (R3 §1.12). music2 ships its own authored minimal Live 12 skeleton XML, assembled from element names, nesting and attribute conventions observed in the permissively licensed fixtures listed in R3 §1.12 (dawtool BSD-3 test .als data, ableton-inspector MIT fixtures, alsd Apache-2.0 tests), with no copied device presets or sample data. Tests never fetch or vendor those fixtures; the skeleton, the observed structural invariants (R3 §4.3/§4.4 oracles) and a round-trip reader over our own output form the automated gate. .als export is labelled experimental until a human opens a generated file in Live 12 and the result is recorded.
D13 DAWproject: vendor Project.xsd and MetaData.xsd (MIT, © 2020 Bitwig, with LICENSE text) under tests/fixtures/dawproject/; xmllint is a test-time optional tool (skip with a recorded reason when absent, CI installs libxml2-utils on Linux); zip entries in reference order metadata.xml, project.xml, then media, using STORE with fixed DOS timestamps.
D14 Plugin bridge licensing (R4 §5.3): pedalboard is GPLv3; music2 core never imports or bundles it. The bridge script that imports pedalboard ships as an optional separate file (scripts/music2-plugin-bridge.py, MIT, documented as user-installed and run as a separate process); music2 talks to any host only through the R4 §6 JSON+WAV subprocess contract. The host command comes from --plugin-host / MUSIC2_PLUGIN_HOST or user config, never from a song file.
D15 Sampler DSP defaults come from R4 §7: resampler kernel per §7.A (windowed-sinc with measured thresholds), time-stretch default WSOLA for percussive/mixed short clips and phase vocoder with identity phase locking (or HP-TSM when justified) per §7.B, onset detection and slicing per §7.C; stretch-factor convention single-sourced (R4 §2.2) and documented.
D16 DAWproject XSD pin (resolves 070 open question): vendor Project.xsd, MetaData.xsd and LICENSE from github.com/bitwig/dawproject commit ee4dcdde75940f30e14e55401a26955a58b8322b (2025-07-12, format 1.0 "stable"); SHA-256: 58e2fd9864772850aac3eab1f3de8693857dc5384df6d29fbc320ae1de2347cc  Project.xsd; fb3ba378271770dddbcced8990aba537de3d36ff2d58573523460a699221c99f  MetaData.xsd; 3aaee5877c9df985f935e40f42f4452182df9e8a8308dcc6cf1a2341458cdfeb  LICENSE. A test asserts these hashes. Manual import check target: none available locally (no Bitwig, Studio One or Cubase installed); the DAW-import result is recorded as unverified unless a human confirms.
