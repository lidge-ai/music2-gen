## 1. Example and fixture contract

The directly renderable song proves note-list timing without sample setup. `track.notes` uses quarter-note beats from the **song start**, never section-relative beats; `pattern` and `notes` are exclusive, and `gate` does not shorten explicit note length (I contract from F5/F10, `010_project_ir.md` §§2–3). Choose an original short arrangement with a pitched hook at known ticks and a gain ramp plus a hold pan change. `events --json` must show the intended onsets, note pitch/velocity and stable section positions; `export ir --json` must show PPQ 960 and list-note `errorTicks:0`. MIDI must retain those list-note ticks (subject to 7-bit velocity) and carry gain/pan as CC7/CC10; a DAW MIDI import is not proof of mixer-fader automation (V, R1 §3.2; I mapping D6/050 §4). Do not alter strict-lint thresholds to make the song pass.

For the second example, test setup chooses a new temporary directory, writes the copied source song there and generates `assets/clip.wav`, `assets/tiny.wav` and `assets/tiny.sfz` beneath it. The SFZ file contains a supported `<region> sample=tiny.wav key=60 pitch_keycenter=60` plus only opcodes implemented by wp5; the audio clip references `assets/clip.wav`. Both are song-relative; SFZ region sample resolution remains confined to its SFZ directory (F6/F8/F20). A fixed WAV frame count and silence-free pitched fixture make audible energy numerically testable, while a bounded `whoosh` clip demonstrates audio-track start, offset, fade and a non-overlapping clip lane. No asset file, generated song copy, absolute path or temporary directory goes into git. The README/skill must give a copyable setup command and explicitly say the nested JSON is a template until fixtures are generated.

Run the fixture-backed song through `validate`, `events`, `lint --strict`, `render`, song-backed `analyze`, and `export ir`; check a nonzero SFZ note window and audio-clip window in PCM/analysis, finite samples, expected frames, correct track ordering (`tracks` then `audioTracks`) and zero A1–A4 balance warnings (`tests/e2e/examples.test.ts:14-17,88-128`; F6/F11). Source facts such as event and frame position are machine-checkable; spectral/RMS measurements do not establish that anyone heard the song (D11). If a fixture fails strict lint or balance analysis, revise arrangement, register, gain, fade or send amounts, then rerun the affected E2E; never suppress a warning by weakening the product gate.

For every route, explain that MIDI transfers notes and selected CC, not music2 voice synthesis, inserts, ducking or all automation; frozen audio/stems preserve sound but are not editable notes (I, F14/F18, 050 §4). DAWproject may contain note and audio lanes with native supported envelopes; XSD validity does not prove a particular DAW will reproduce music2 DSP (V R3 §2.8, I limitation). Document `--content midi|audio|both` defaults and duplication, whether sample audio is included, and imported output licensing responsibility. Avoid saying FL or Ableton natively imports DAWproject without fresh primary proof (R3 §2.9).
