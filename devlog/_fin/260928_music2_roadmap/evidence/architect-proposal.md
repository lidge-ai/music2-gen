# Architect proposal (verbatim, sol 01a0e37e-3635-72b2-a410-a984adb4532a, 2026-09-28)

**설계 판정: v0.1은 JSON 악보를 단일 시간축으로 확정한 뒤, 자체 패턴 질의·오프라인 렌더·분석을 차례로 얹는 구조가 적합합니다.** 아래는 부모 작업자가 채택하거나 수정할 수 있는 결정안입니다. 조사만 수행했고 파일은 수정하지 않았습니다.

**D1 — 모듈 경계.** `src/song/`(스키마·배치), `src/pattern/`(파서·질의), `src/render/`(스케줄·보이스·믹스·WAV), `src/analyze/`(DSP·시각화·beat map), `src/recipes/`, `src/critic/`, `src/cli/`, `src/shared/`를 제안합니다. 각 기능의 주 진입점은 `name.tool.ts`, 검증은 `name.test.ts`, 외부 공개 경계만 `index.ts`; 기능 내부는 소스 파일을 직접 import합니다. 의존 방향은 CLI → 기능 경계 → song/pattern 계약이며 critic과 ffmpeg는 렌더 핵심으로 역류하지 않습니다. 대안인 단일 `audio/` 폴더는 처음엔 작지만 분석·렌더 책임이 섞입니다. 근거: `../vid2-gen/src/cli/registry.ts:18`, `../vid2-gen/devlog/_plan/260927_vid2_roadmap/010_foundations.md:23`. 가정: 공개 라이브러리 API는 소수의 기능 경계만 노출합니다.

**D2 — song schema v1.** 최상위는 `version:1`, `bpm`, `meter:{numerator,denominator}`, `key`, `seed`, `tracks`, `sections`, `arrangement`, 선택적 `bars` 검산값입니다. 트랙은 고유 `id`, `kind:"drum"|"note"`, `instrument`, 기본 `pattern`, `velocity`, `gain`, `pan`, `sends`, `fx`, 선택적 `seed`를 갖습니다. 섹션은 `bars`와 트랙 ID별 패턴 재정의만 갖고, arrangement는 `{section, repeats}`의 순서 목록입니다. 각 반복의 패턴은 해당 섹션 첫 바에서 다시 시작하며 전체 길이는 합산하고 명시된 `bars`와 불일치하면 오류로 처리합니다. 대안인 트랙별 절대 바 배치는 짧은 편집엔 편하나 섹션 재사용이 어렵습니다. 근거: `/tmp/music2-poc/render.mjs:9`, `../vid2-gen/src/timeline/schema.ts:80`. 가정: v1에는 템포·박자 변경이 없습니다.

**D3 — mini-notation 범위.** v0.1은 공백 순차, `[]` 세분, `<>` 다중 사이클, `~` 쉼, `,` 동시음, 정수 `*`, `/`, `!`만 구현하고 미지원 문법은 위치가 있는 구문 오류로 냅니다. 노트 트랙은 `c#4` 같은 피치, 드럼 트랙은 kit 심벌만 허용합니다. 확률 `?`, 선택 `|`, Euclidean, 가중치 `@`, 소수 배속은 보류합니다. 이 일부 문법은 PoC가 실제 사용한 중첩·쉼·코드와 [Strudel 공개 문서](https://strudel.cc/learn/mini-notation/)에 맞춥니다. 전체 Strudel 호환을 약속하는 대안은 구현·검증 범위를 과도하게 키웁니다. 근거: `/tmp/music2-poc/render.mjs:11`, `/tmp/music2-poc/render.mjs:16`. 가정: 보류 문법이 들어 있는 레시피는 제공하지 않습니다.

**D4 — 패턴 질의.** 파서는 불변 AST를 만들고 시간은 정규화한 유리수 사이클로 계산합니다. `queryArc(start,end)`는 `[start,end)`에 겹치는 이벤트를 `{whole,part,value}`로 반환하고, 렌더 스케줄러는 `whole.begin`이 질의 구간에 있는 onset만 채택해 경계 중복을 막습니다. `part`는 긴 음의 구간 절단·시각화에 남겨둡니다. 대안인 즉시 초 단위 `number` 확장은 중첩 패턴의 바 경계에서 오차가 누적됩니다. 근거: `/tmp/music2-poc/render.mjs:18`. 가정: AST 깊이·분모·이벤트 수 상한을 스키마와 질의 경계에서 둡니다.

**D5 — 렌더 그래프.** `Event → Voice.render(frame range, state) → track FX/gain/pan → dry bus + reverb/delay sends → sidechain duck → master soft clip/peak control → WAV`를 제안합니다. 보이스는 킥·스네어·햇·FM·플럭·패드·베이스·샘플을 구현하고, 808은 트랙당 단일 위상·피치 상태로 다음 onset까지 글라이드합니다. 샘플 kit manifest는 심벌→상대 WAV 경로·기준 피치·기본 gain을 명시하고 로컬 PCM WAV만 읽습니다. 대안인 범용 플러그인 체인은 v0.1의 재현성과 경계를 약화합니다. 근거: `/tmp/music2-poc/render.mjs:27`, `/tmp/music2-poc/render.mjs:32`, `/tmp/music2-poc/render.mjs:67`. 가정: 리버브 tail은 전체 길이 뒤에 고정된 최대 tail 또는 무음 임계 종료로 명시합니다.

**D6 — 결정성과 WAV.** 렌더 이벤트 정렬은 절대 onset → 트랙 순서 → 패턴 내 순서로 고정하고, 잡음 PRNG는 song/track/event seed에서 독립 파생합니다. 음성 계산에 `Date`·`Math.random`을 쓰지 않고 동일 샘플레이트·연산 순서·디더 규칙을 고정합니다. 16/24-bit PCM stereo WAV를 청크로 기록해 긴 곡의 전량 버퍼 복사를 피합니다. 대안인 전역 순차 PRNG는 트랙 하나를 추가해도 다른 트랙 소리가 바뀝니다. PoC의 단일 seed·44-byte 헤더는 출발점일 뿐입니다. 근거: `/tmp/music2-poc/render.mjs:24`, `/tmp/music2-poc/render.mjs:73`. 가정: 바이트 동일성 보장은 같은 Node/플랫폼 조건으로 한정하고 교차 플랫폼은 별도 검증합니다.

**D7 — ffmpeg 경계.** 기본 `render`는 ffmpeg 없이 WAV를 냅니다. `--loudnorm`, `--mp3`, `--ogg` 요청 때만 실행 파일을 탐지하고, shell 없이 인자를 전달하며 부재 시 `E_CAPABILITY`을 냅니다. loudnorm은 파일 대상 2-pass를 권장하고 결과의 측정값을 별도 기록합니다. [FFmpeg 문서](https://www.ffmpeg.org/ffmpeg-filters.html#loudnorm)는 이 필터의 1-pass·2-pass와 integrated loudness·true peak 목표를 명시합니다. 대안인 ffmpeg 필수화는 “오프라인 기본 WAV” 계약을 약화합니다. 근거: `../vid2-gen/src/shared/errors.ts:3`, `/tmp/music2-poc/render.mjs:75`. 가정: 출력 코덱 사용 가능 여부는 `doctor`가 기능별로 보고합니다.

**D8 — 분석과 beat map.** `analyze`는 PCM 기준 샘플 피크·클리핑·대역 에너지, K-weighted gated LUFS, oversampled true peak, STFT spectral flux onset, 자기상관 템포 후보, chroma 기반 key 후보와 confidence를 냅니다. 악보가 있으면 `declaredBpm`과 독립 `estimatedBpm`을 분리해 half/double-time 모호성을 숨기지 않습니다. `beats.json` 최상위에 `bpm`, `meter`, `offsetFrames:0`을 둬 vid2-gen 현재 reader가 바로 소비하게 하고, `source`, `confidence`, `beatsSeconds` 등은 추가 필드로 둡니다. 대안인 AI critic 수치를 공식 템포로 채택하는 방식은 PoC에서 140 BPM 클립을 145/124로 판정한 결과와 맞지 않습니다. 근거: `../vid2-gen/src/timeline/resolve.ts:54`, `/tmp/music2-poc/probe-results.md:4`. 가정: `offsetFrames`는 vid2 영상 프레임이므로 music2 산출물에서는 0만 약속합니다.

**D9 — 두 PNG.** `spectrogram.png`는 시간×로그 주파수 STFT 크기와 범례, `piano-roll.png`는 song 이벤트의 피치×바 위치·트랙 색을 표시합니다. WAV만 입력한 경우 피치 전사인 척하지 않고 piano roll을 “악보 없음” 상태로 생략하거나 명시적 capability 오류를 냅니다. `vid2-gen/src/compile/png.ts`의 PNG chunk/CRC/`node:zlib` 방식을 MIT 라이선스·저작권 표기를 확인한 뒤 필요한 인코더 부분만 독립 구현합니다. 대안인 외부 PNG 패키지는 zero-runtime-dependency 계약에 어긋납니다. 근거: `../vid2-gen/src/compile/png.ts:6`, `../vid2-gen/src/compile/png.ts:27`. 가정: spectrogram 색상맵·축 범위를 출력 JSON에도 기록합니다.

**D10 — critic transport.** `critique`는 설정된 Responses URL·모델로 `input_text`와 `input_file`의 `data:audio/mpeg;base64,...`를 전송하고, `heard_audio:true` 및 구조화 응답을 확인합니다. 불가·거절·지원되지 않는 modality는 `E_CAPABILITY`(재시도 가능한 서버 장애는 `E_PROVIDER`)로 반환하며, DSP 수치를 critic 응답으로 덮어쓰지 않습니다. MP3가 필요한 경로에서 ffmpeg가 없으면 전송 전에 같은 capability 오류를 냅니다. `/v1/models`의 modality 표시는 판별 근거로 쓰지 않습니다. 대안인 `input_audio`는 해당 로컬 probe에서 거절됐습니다. 근거: `/tmp/music2-poc/probe2.mjs:7`, `/tmp/music2-poc/probe-results.md:2`. 가정: 원격 OpenAI 호환 서버의 오디오 지원은 실행 때마다 검증합니다.

**D11 — CLI 계약.** `render`, `analyze`, `new`, `lint`, `recipes`, `critique`, `doctor`, `schema`를 등록하고 모든 명령에 `--json` 및 명령별 `--help`를 적용합니다. JSON 모드는 stdout에 성공·실패 객체 **한 개만** 쓰고 진행·진단은 stderr로 보냅니다. 종료 코드는 vid2와 같은 0 성공, 1 내부, 2 입력/스키마, 3 capability, 4 접근/provider, 5 render, 6 QA/lint 실패, 7 중단을 제안합니다. 대안인 명령별 임의 출력은 agent 파싱을 어렵게 합니다. 근거: `../vid2-gen/src/cli/main.ts:12`, `../vid2-gen/src/cli/output.ts:11`, `../vid2-gen/src/shared/errors.ts:3`. 가정: `schema --json`도 단일 envelope 안에 스키마를 넣습니다.

**D12 — 레시피와 lint.** 레시피 카드는 `id`, `version`, `bpmRange`, `meter`, `scaleHints`, `requiredRoles`, `gridRules`, `bassRules`, `palette`, `mixTargets`, `starterSong`를 가진 데이터 파일로 둡니다. lint 규칙은 `{id,severity,location,observed,expected,fix}` 결과를 반환하고, 문법·없는 샘플·범위 위반은 error, 장르 관행과 믹스 목표는 warning으로 분리합니다. `new`는 카드의 starterSong을 복사해 사용자 seed와 제목을 채웁니다. 대안인 장르별 하드코딩 함수는 규칙 설명과 생성 템플릿의 드리프트를 키웁니다. 근거: `/tmp/music2-poc/objective.txt:7`, `../vid2-gen/src/cli/output.ts:4`. 가정: 장르 규칙은 미학적 판정이 아닌 검사 가능한 휴리스틱으로 표시합니다.

**D13 — 검증과 wp2–wp6 순서.** wp2는 package/CLI/song schema/패턴 질의와 golden 이벤트 테스트, wp3은 보이스·kit·WAV 결정성, wp4는 분석·PNG·vid2 beat-map 계약, wp5는 레시피·lint·critic, wp6은 문서·예제·agent dogfood와 패키지/CI 확인 순서가 맞습니다. 앞 단계의 공개 계약과 golden fixture가 다음 단계의 입력이 되기 때문입니다. CI는 Node 22/24와 주요 OS에서 typecheck·lint·unit·짧은 실제 렌더·동일 SHA 두 번·PNG decode·CLI JSON/exit·pack smoke를 수행하고, ffmpeg/critic 검사는 선택 기능과 모의 transport를 나눕니다. 대안인 critic을 렌더 전에 만드는 순서는 측정 가능한 오디오 계약 없이 원격 응답에 의존합니다. 근거: `/tmp/music2-poc/objective.txt:14`, `../vid2-gen/scripts/test.mjs:33`, `../vid2-gen/.github/workflows/ci.yml:16`. 가정: 실제 opencodex 연결은 CI 필수 조건이 아니라 별도 현장 검증입니다.

남은 가정은 네 가지입니다: `meter`의 분모를 v1에서 4로 제한할지, 노트 길이를 패턴 슬롯 전체로 할지 gate 비율을 둘지, 샘플 WAV의 허용 포맷·라이선스 정책, LUFS/true-peak 구현의 허용 오차입니다. 특히 독립 BPM 추정의 ±2 검증은 half-time 드릴에서 모호할 수 있으므로, 선언 BPM을 보정 힌트로 쓰는지와 독립 추정 성능을 별도 합격 조건으로 둘지 부모가 확정해야 합니다.
